## 1. Что такое динамический массив

**Обычный (статический) массив** хранит элементы подряд в памяти и имеет **фиксированный размер**, заданный при создании. Добавить в него элемент сверх этого размера нельзя — нужно создавать новый массив.

**Динамический массив** решает эту проблему: снаружи он выглядит как массив, который можно свободно расширять (`append`), но внутри он устроен как **статический массив большего размера**, чем реально нужно, плюс счётчик, сколько ячеек занято.

```
Реально используется:        [1][3][7][2]
Выделено в памяти:            [1][3][7][2][ ][ ][ ][ ]
                                            ↑
                                    "запас" на будущее
```

Когда запас заканчивается, массив **не растёт по одной ячейке**, а полностью пересоздаётся большего размера — обычно **в 2 раза больше**. Именно этот приём делает добавление элемента быстрым **в среднем**, хотя отдельные вставки могут быть медленными.

> **Аналогия.** Представьте, что вы снимаете офис. Можно каждый раз при найме одного нового сотрудника переезжать в помещение ровно на одно место больше — но переезды (со всей мебелью) будут происходить постоянно. А можно сразу арендовать офис с запасом в два раза больше текущего штата: переезды станут редкими, а по большей части просто сажаете новых сотрудников за свободные столы.

`list` в Python — это и есть динамический массив. Всё, что описано ниже, объясняет, как он устроен и почему ведёт себя именно так.

## 2. Основные операции и их сложность

| Операция | Сложность | Почему |
|---|---|---|
| `arr[i]` — доступ по индексу | O(1) | адрес ячейки вычисляется напрямую: `начало + i * размер_элемента` |
| `arr[i] = x` — изменение по индексу | O(1) | то же самое |
| `arr.append(x)` — добавить в конец | O(1) **амортизированно** | почти всегда просто запись в свободную ячейку, изредка — пересоздание массива |
| `arr.pop()` — удалить с конца | O(1) | просто уменьшаем счётчик занятых ячеек |
| `arr.insert(i, x)` — вставить в середину | O(n) | нужно сдвинуть все элементы после `i` на одну позицию вправо |
| `arr.pop(i)` — удалить из середины | O(n) | нужно сдвинуть все элементы после `i` на одну позицию влево |
| `x in arr` — поиск элемента | O(n) | нет иного способа, кроме перебора |
| перебор всех элементов | O(n) | ожидаемо |

Ключевая особенность динамического массива — **быстрый доступ по индексу** и **быстрое добавление в конец**, но **медленная вставка/удаление в произвольном месте**. Это прямо противоположно связному списку (linked list), где легко вставлять в середину, но нет быстрого доступа по индексу.

## 3. Почему `append` — O(1) в среднем, а не всегда

Разберём на примере стратегии **удвоения**.

```
Ёмкость (capacity) = 4, занято (size) = 4      [1][3][7][2]
append(9):
  свободных ячеек нет → выделяем новый массив ёмкостью 8,
  копируем туда все 4 старых элемента, затем добавляем 9

Ёмкость = 8, занято = 5      [1][3][7][2][9][ ][ ][ ]

append(5), append(4), append(8):
  свободные ячейки есть → просто дозаписываем

Ёмкость = 8, занято = 8      [1][3][7][2][9][5][4][8]

append(6):
  снова нет места → выделяем массив ёмкостью 16, копируем 8 элементов
```

Отдельная операция `append`, вызвавшая пересоздание, стоит O(n) — надо скопировать все существующие элементы. Но такие пересоздания происходят **всё реже**: после k-го удвоения массив не растёт ещё k шагов. Если просуммировать стоимость всех `append` от пустого массива до размера n, получится:

```
n (сами записи) + (1 + 2 + 4 + 8 + ... + n) (копирования) ≈ n + 2n = 3n
```

То есть суммарная работа на n вставок — **O(n)**, а значит, в среднем одна вставка стоит **O(1)**. Это и называется **амортизированной сложностью** — не каждая отдельная операция быстрая, но быстрая *в среднем на серию операций*.

### Почему именно удвоение, а не «+1» или «+10»

- Если увеличивать ёмкость на фиксированное число (например, +1 каждый раз), придётся копировать данные при **каждой** вставке → O(n) на каждый `append`, O(n²) суммарно на n вставок. Это и есть тот самый «наивный» медленный вариант.
- Если увеличивать **в constant раз** (×2, ×1.5 и т.п.), количество пересозданий растёт логарифмически (log₂ n раз при удвоении), и суммарная стоимость остаётся линейной. Коэффициент роста — компромисс между экономией памяти (меньше — экономнее) и частотой пересозданий (больше — реже копируем). CPython использует коэффициент роста примерно ×1.125, плюс небольшую добавку — это чуть экономнее по памяти, чем ×2, но суть та же.

## 4. Собственная реализация динамического массива

Ниже — упрощённая реализация на чистом Python поверх низкоуровневого модуля `ctypes`, который позволяет выделять массивы фиксированного размера (сам `list` внутри устроен похоже, но на языке C).

```python
import ctypes


class DynamicArray:
    """Простой динамический массив с удвоением ёмкости."""

    def __init__(self):
        self._size = 0          # сколько элементов реально хранится
        self._capacity = 1      # сколько ячеек выделено под данные
        self._array = self._make_array(self._capacity)

    # ---------- служебное ----------

    def _make_array(self, capacity):
        """Создать низкоуровневый массив ссылок фиксированного размера."""
        return (capacity * ctypes.py_object)()

    def _resize(self, new_capacity):
        """Выделить массив большего размера и скопировать в него элементы."""
        new_array = self._make_array(new_capacity)
        for i in range(self._size):
            new_array[i] = self._array[i]
        self._array = new_array
        self._capacity = new_capacity

    # ---------- публичный интерфейс ----------

    def __len__(self):
        return self._size

    def __getitem__(self, i):
        if not 0 <= i < self._size:
            raise IndexError("index out of range")
        return self._array[i]

    def __setitem__(self, i, value):
        if not 0 <= i < self._size:
            raise IndexError("index out of range")
        self._array[i] = value

    def append(self, value):
        if self._size == self._capacity:
            self._resize(2 * self._capacity)   # удваиваем ёмкость
        self._array[self._size] = value
        self._size += 1

    def pop(self):
        if self._size == 0:
            raise IndexError("pop from empty array")
        value = self._array[self._size - 1]
        self._size -= 1
        return value

    def insert(self, i, value):
        if not 0 <= i <= self._size:
            raise IndexError("index out of range")
        if self._size == self._capacity:
            self._resize(2 * self._capacity)
        # сдвигаем элементы вправо, начиная с конца
        for j in range(self._size, i, -1):
            self._array[j] = self._array[j - 1]
        self._array[i] = value
        self._size += 1

    def __repr__(self):
        return "[" + ", ".join(str(self._array[i]) for i in range(self._size)) + "]"
```

Проверка:

```python
arr = DynamicArray()
for x in [1, 3, 7, 2]:
    arr.append(x)

print(arr)          # [1, 3, 7, 2]
print(len(arr))      # 4
arr.insert(1, 99)
print(arr)           # [1, 99, 3, 7, 2]
print(arr.pop())      # 2
print(arr)            # [1, 99, 3, 7]
```

### Уменьшение ёмкости (shrink)

Если элементы часто удаляют, полезно не только увеличивать массив, но и **уменьшать** его, когда он становится сильно недозаполнен — иначе память расходуется впустую. Обычно ёмкость уменьшают вдвое, когда заполненность падает ниже 1/4:

```python
def pop(self):
    if self._size == 0:
        raise IndexError("pop from empty array")
    value = self._array[self._size - 1]
    self._size -= 1
    if self._size <= self._capacity // 4 and self._capacity > 1:
        self._resize(max(1, self._capacity // 2))
    return value
```

Порог берут не 1/2, а 1/4 — иначе при чередовании `append`/`pop` возле границы ёмкость будет пересоздаваться туда-сюда на каждой операции (это называют «дребезгом» / thrashing), и амортизированная O(1) превратится в O(n).

## 5. Ёмкость и размер в Python: `len()` и «запас»

В самом Python нет прямого способа посмотреть текущую *ёмкость* списка — только реальный размер через `len()`. Но можно подглядеть, сколько байт занимает список в памяти, и увидеть, что оно растёт скачками, а не на 1:

```python
import sys

lst = []
prev = sys.getsizeof(lst)
for i in range(10):
    lst.append(i)
    size = sys.getsizeof(lst)
    if size != prev:
        print(f"после {i + 1}-го append: {prev} -> {size} байт (выделен новый блок)")
        prev = size
```

Типичный вывод покажет, что размер в байтах меняется не на каждой вставке, а лишь изредка — это и есть моменты пересоздания внутреннего массива.

## 6. Список (`list`) в Python — практика

### 6.1. Базовые операции

```python
arr = [1, 3, 7, 2]

arr.append(9)          # [1, 3, 7, 2, 9]      O(1) амортизированно
arr.insert(0, 100)      # [100, 1, 3, 7, 2, 9]  O(n)
arr.pop()                # 9, [100, 1, 3, 7, 2] O(1)
arr.pop(0)               # 100, [1, 3, 7, 2]    O(n)
arr.remove(7)             # удалить ПЕРВОЕ вхождение значения 7, O(n)
print(3 in arr)            # O(n) поиск
```

**Частая ошибка:** `arr.remove(x)` удаляет по **значению**, а `arr.pop(i)` — по **индексу**. Их легко перепутать.

### 6.2. Срезы (slices) — тоже O(n)

```python
arr = [0, 1, 2, 3, 4, 5]
print(arr[1:4])     # [1, 2, 3]   — новый список, копирование O(k)
print(arr[::-1])    # [5, 4, 3, 2, 1, 0]  — разворот через срез

arr[1:3] = [10, 20, 30]   # можно заменить срез списком другой длины
print(arr)                 # [0, 10, 20, 30, 3, 4, 5]
```

Срез создаёт **новый** список — исходный не меняется (кроме варианта присваивания в срез, как выше).

### 6.3. Расширение списка: `append` vs `extend`

```python
a = [1, 2, 3]
b = [4, 5]

a.append(b)     # [1, 2, 3, [4, 5]]   ← добавил список КАК ОДИН элемент
a2 = [1, 2, 3]
a2.extend(b)     # [1, 2, 3, 4, 5]     ← добавил каждый элемент по отдельности
a3 = [1, 2, 3]
a3 += b            # то же самое, что extend
```

`extend(iterable)` работает за O(k), где k — длина добавляемой последовательности, а не за O(k) отдельных `append` (хотя асимптотика та же, `extend` эффективнее на практике за счёт меньшего числа проверок ёмкости).

### 6.4. List comprehension — создание массива

```python
squares = [x * x for x in range(10)]
evens = [x for x in range(20) if x % 2 == 0]
```

List comprehension обычно быстрее, чем ручной цикл с `append`, потому что интерпретатор заранее оценивает объём работы и меньше обращается к атрибутам объекта на каждой итерации.

## 7. Динамический массив vs связный список

| | Динамический массив | Связный список |
|---|---|---|
| Доступ по индексу `arr[i]` | O(1) | O(n) |
| Добавление в конец | O(1) амортизированно | O(1), если хранить указатель на хвост |
| Добавление в начало | O(n) | O(1) |
| Вставка в середину (индекс известен) | O(n) — сдвиг | O(1) — если уже есть указатель на узел |
| Память | компактнее (нет указателей на соседей) | больше накладных расходов (указатели) |
| Кэш-локальность | хорошая: элементы подряд в памяти | плохая: узлы разбросаны по памяти |

**Вывод:** если нужен частый доступ по индексу и добавление в конец — берите динамический массив (`list`). Если нужны частые вставки/удаления в начале или середине по известной позиции — связный список может быть выгоднее. На практике в Python `list` почти всегда быстрее на реальных задачах за счёт кэш-локальности, даже там, где теоретически связный список «должен» выигрывать.

## 8. Типичные задачи и приёмы

### 8.1. Два указателя (two pointers)

Часто используется, чтобы обработать массив за O(n) без вложенных циклов.

```python
def has_pair_with_sum(arr, target):
    """arr отсортирован. Есть ли два числа с суммой target?"""
    left, right = 0, len(arr) - 1
    while left < right:
        s = arr[left] + arr[right]
        if s == target:
            return True
        elif s < target:
            left += 1     # сумма мала — двигаем левый указатель вправо
        else:
            right -= 1    # сумма велика — двигаем правый указатель влево
    return False


print(has_pair_with_sum([1, 2, 4, 7, 11], 15))   # True (4 + 11)
```

### 8.2. Скользящее окно (sliding window)

```python
def max_subarray_sum(arr, k):
    """Максимальная сумма подряд идущих k элементов, O(n)."""
    window_sum = sum(arr[:k])
    best = window_sum
    for i in range(k, len(arr)):
        window_sum += arr[i] - arr[i - k]   # добавили новый, убрали старый
        best = max(best, window_sum)
    return best


print(max_subarray_sum([2, 1, 5, 1, 3, 2], 3))   # 9  (5 + 1 + 3)
```

Наивное решение пересчитывало бы сумму каждого окна заново за O(k), и всего было бы O(n·k). Скользящее окно переиспользует предыдущую сумму и работает за O(n).

### 8.3. Префиксные суммы (prefix sums)

Позволяют отвечать на запросы «сумма элементов от i до j» за O(1) после предварительной подготовки за O(n).

```python
def build_prefix_sums(arr):
    prefix = [0] * (len(arr) + 1)
    for i, x in enumerate(arr):
        prefix[i + 1] = prefix[i] + x
    return prefix


def range_sum(prefix, i, j):
    """Сумма arr[i..j] включительно."""
    return prefix[j + 1] - prefix[i]


arr = [4, 2, 7, 1, 5]
prefix = build_prefix_sums(arr)      # [0, 4, 6, 13, 14, 19]
print(range_sum(prefix, 1, 3))        # 2 + 7 + 1 = 10
```

### 8.4. Удаление дубликатов на месте (in-place), два указателя

```python
def remove_duplicates(arr):
    """arr отсортирован. Убрать дубликаты на месте, вернуть новую длину."""
    if not arr:
        return 0
    write = 1                       # позиция, куда пишем следующий уникальный элемент
    for read in range(1, len(arr)):
        if arr[read] != arr[write - 1]:
            arr[write] = arr[read]
            write += 1
    return write


arr = [1, 1, 2, 2, 2, 3, 4, 4]
new_len = remove_duplicates(arr)
print(arr[:new_len])   # [1, 2, 3, 4]
```

Приём «два указателя, один читает — другой пишет» — классический способ работать **без выделения дополнительной памяти**, за O(n).

### 8.5. Разворот массива на месте

```python
def reverse(arr):
    left, right = 0, len(arr) - 1
    while left < right:
        arr[left], arr[right] = arr[right], arr[left]
        left += 1
        right -= 1


arr = [1, 2, 3, 4, 5]
reverse(arr)
print(arr)   # [5, 4, 3, 2, 1]
```

## 9. Частые ошибки

1. **Считать `list.append` всегда O(1).** Отдельный вызов иногда стоит O(n) из-за пересоздания массива — но в среднем всё равно O(1). Для одиночной вставки в реальном времени (например, в системе с жёстким ограничением по времени) это иногда важно.
2. **Вставлять или удалять в начале списка в цикле.** `arr.insert(0, x)` и `arr.pop(0)` — это O(n) каждый раз, а в цикле — O(n²) суммарно. Если нужны частые операции с обоих концов — используйте `collections.deque`, а не `list`.
   ```python
   from collections import deque
   dq = deque([1, 2, 3])
   dq.appendleft(0)   # O(1), а не O(n), как было бы у list.insert(0, ...)
   dq.popleft()        # O(1)
   ```
3. **Изменять список во время итерации по нему.** Удаление элементов в `for x in arr: arr.remove(x)` пропускает элементы, потому что индексы сдвигаются. Правильно — идти с конца, использовать копию или list comprehension.
   ```python
   arr = [1, 2, 3, 4, 5]
   # неправильно: arr.remove(x) внутри for x in arr — часть элементов пропустится
   arr = [x for x in arr if x % 2 != 0]   # правильно: новый список
   ```
4. **Путать копирование и ссылку.** `b = a` не создаёт копию — `b` и `a` указывают на один и тот же список.
   ```python
   a = [1, 2, 3]
   b = a
   b.append(4)
   print(a)   # [1, 2, 3, 4]  ← изменился и a тоже!

   c = a.copy()        # или a[:], или list(a) — поверхностная копия
   c.append(5)
   print(a)             # без изменений
   ```
5. **Поверхностная (shallow) копия при вложенных списках.** `copy()` копирует только внешний список; вложенные списки остаются общими.
   ```python
   import copy
   a = [[1, 2], [3, 4]]
   b = a.copy()
   b[0].append(99)
   print(a)   # [[1, 2, 99], [3, 4]]  ← вложенный список общий!

   c = copy.deepcopy(a)   # полностью независимая копия
   ```
6. **Использовать `list` там, где нужен поиск по значению часто.** Поиск `x in list` — O(n). Если поиск по значению нужен часто — используйте `set` или `dict` (O(1) в среднем).

## 10. Шпаргалка

```python
arr = []                      # пустой динамический массив

arr.append(x)                 # добавить в конец, O(1) амортизированно
arr.pop()                     # удалить с конца, O(1)
arr.insert(i, x)              # вставить по индексу, O(n)
arr.pop(i)                    # удалить по индексу, O(n)
arr.remove(x)                 # удалить по значению (первое вхождение), O(n)
arr[i]                        # доступ по индексу, O(1)
x in arr                      # поиск по значению, O(n)
arr.extend(other)             # добавить много элементов, O(k)
arr[:]                        # копия списка, O(n)
arr[::-1]                     # развёрнутая копия, O(n)
len(arr)                      # размер, O(1)

# нужны быстрые операции с ОБОИХ концов → collections.deque
# нужен быстрый поиск по значению → set / dict
```

Правило по умолчанию: **`list` хорош для доступа по индексу и роста в конце. Всё, что требует частых операций в начале/середине — повод посмотреть в сторону `deque`, `set` или `dict`.**

## 11. Вопросы для самопроверки

1. Почему `append` называют O(1) *амортизированным*, а не просто O(1)?
2. Почему ёмкость увеличивают в constant раз (×2), а не на фиксированное число?
3. Чем `list.remove(x)` отличается от `list.pop(i)`?
4. Какая сложность у `arr.insert(0, x)` и почему?
5. Почему `b = a.copy()` не спасает от общих изменений, если `a` — список списков?

<details>
<summary>Ответы</summary>

1. Потому что отдельные вызовы `append` иногда стоят O(n) (когда происходит пересоздание массива), но если посчитать суммарную стоимость n вызовов подряд, она окажется O(n), то есть в среднем на одну операцию — O(1).
2. При увеличении на constant раз число пересозданий растёт логарифмически, и суммарная стоимость n вставок остаётся O(n). При увеличении на фиксированное число пересоздание происходит при каждой вставке, и суммарная стоимость становится O(n²).
3. `remove(x)` ищет первое вхождение **значения** `x` и удаляет его — O(n) на поиск. `pop(i)` удаляет элемент по **индексу** — сразу переходит к нужной позиции, но всё равно O(n) на сдвиг оставшихся элементов (кроме `pop()` без аргумента — O(1), удаление с конца).
4. O(n), потому что после вставки в начало все существующие элементы нужно сдвинуть на одну позицию вправо.
5. `copy()` делает **поверхностную** копию: копируется только внешний список, а вложенные списки внутри остаются теми же объектами (общими для `a` и `b`). Нужна `copy.deepcopy(a)`, чтобы получить полностью независимую копию на всех уровнях вложенности.

</details>
