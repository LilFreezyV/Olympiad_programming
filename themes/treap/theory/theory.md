## 1. Что такое Treap

**Treap** (tree + heap), или декартово дерево, совмещает двоичное дерево поиска и кучу. У каждого узла есть ключ `key` и случайный приоритет `priority`.

> **Аналогия.** Представьте людей в очереди: место в очереди определяется номером (ключом), а право подняться выше — случайным «уровнем важности» (приоритетом). В итоге дерево одновременно упорядочено по ключам и по приоритетам.

### 1.1. Два свойства дерева

Для каждого узла выполняются сразу два правила:

1. **BST по ключам:** слева ключи меньше ключа узла, справа — больше.
2. **Heap по приоритетам:** при max-heap приоритет родителя больше приоритетов детей.

Пример max-heap по приоритетам:

```
                (8, 95)
               /       \
          (3, 72)      (12, 81)
          /    \          /
      (1, 40) (6, 58)  (10, 33)
```

Пары записаны как `(ключ, приоритет)`. По ключам выполняется BST, по вторым числам — max-heap.

Если все приоритеты различны, то для заданных пар `(key, priority)` форма дерева **единственна**: это BST по ключам и heap по приоритетам одновременно.

### 1.2. Почему высота ожидаемо логарифмическая

Если приоритеты независимы и равномерно случайны, порядок узлов по приоритетам похож на случайный порядок вставки в BST. Поэтому ожидаемая высота — O(log n), а операции обычно занимают O(log n).

Это **ожидаемая**, а не строгая гарантия: неудачные приоритеты могут дать высоту O(n). Случайные приоритеты делают такую форму маловероятной. Для устойчивости к намеренно подобранным входам используйте генератор случайных чисел, не зависящий от ключей, или встроенную сбалансированную структуру языка.

## 2. Treap по ключу

Treap по ключу хранит упорядоченное множество (или мультимножество) и поддерживает динамические операции. Код находится в `themes/treap/code/ordered_treap.py`.

### 2.1. Узел и агрегаты

Минимальный узел содержит ключ, приоритет и ссылки на детей. Часто хранят также агрегаты поддерева: размер, сумму, минимум и другие значения.

```text
size(t)  = 1 + size(t.left) + size(t.right)
sum(t)   = t.key + sum(t.left) + sum(t.right)
```

После изменения детей нужно пересчитать агрегаты. В примере это делает `update(t)`.

### 2.2. Операции split и merge

**`split(t, k)`** в сохранённом `code/split.py` делит дерево на два: ключи `<= k` и ключи `> k`. Дерево перестраивается вдоль одного пути от корня, поэтому ожидаемое время O(log n).

**`merge(a, b)`** объединяет деревья, если все ключи в `a` меньше ключей в `b`. Корнем становится узел с большим приоритетом; остальные узлы рекурсивно присоединяются как его поддерево.

#### Пошаговый пример `split`

Возьмём `k = 6`. Узел записан как `(x, y)`: `x` — ключ, `y` — приоритет. Дерево соблюдает BST по `x` и max-heap по `y`:

```text
                 (8, 95)
                /       \\
          (3, 72)       (12, 81)
          /    \\
      (1, 40) (6, 58)
```

В `code/split.py` условие `a.x > k` отправляет узел в правую часть. Идём по пути:

1. В `(8, 95)`: `8 > 6`, значит рекурсивно делим левое поддерево. При возврате строка `left, a.left = split(...)` заберёт левую часть результата отдельно, а правую присоединит к `(8, 95)`.
2. В `(3, 72)`: `3 > 6` ложно, идём в правое поддерево `(6, 58)`. При возврате строка `a.right, right = split(...)` присоединит левую часть результата к `(3, 72)`, а правую вернёт отдельно.
3. В `(6, 58)`: `6 > 6` ложно, идём вправо в `None`. Для пустого узла срабатывает `return None, None`.
4. Возвращаясь к `(6, 58)`, присваиваем пустые результаты и возвращаем `(6, 58)` в левую часть.
5. Возвращаясь к `(3, 72)`, оставляем `(6, 58)` его правым ребёнком и возвращаем `(3, 72)` вместе с `(1, 40)` в левую часть.
6. Возвращаясь к `(8, 95)`, отсоединяем левое поддерево и возвращаем `(8, 95)` с `(12, 81)` в правую часть.

Итог: слева ключи `<= 6`, справа ключи `> 6`:

```text
Первое дерево:             Второе дерево:
   (3, 72)                    (8, 95)
   /    \\                          \\
(1, 40) (6, 58)                 (12, 81)
```

#### Пошаговый пример `merge`

Все ключи в `a` меньше ключей в `b`; приоритеты образуют max-heap:

```text
a:                         b:
      (3, 70)                    (8, 90)
      /    \\                    /    \\
 (1, 40) (5, 60)           (7, 50) (10, 30)
```

Разбираем строки из `code/merge.py`:

1. `(3, 70)` против `(8, 90)`: `a.y > b.y` ложно. Выполняется `b.left = merge(a, b.left)` — следующий вызов с `(3, 70)` и `(7, 50)`.
2. `(3, 70)` против `(7, 50)`: условие истинно. `a.right = merge(a.right, b)` вызывает `merge((5, 60), (7, 50))`.
3. `(5, 60)` против `(7, 50)`: условие истинно. Эта же строка вызывает `merge(None, (7, 50))`.
4. Базовый случай `if a is None: return b` возвращает `(7, 50)`.
5. При возврате `(7, 50)` становится правым ребёнком `(5, 60)`; `return a` возвращает `(5, 60)`.
6. Затем `(5, 60)` становится правым ребёнком `(3, 70)`; `return a` возвращает `(3, 70)`.
7. Наконец `(3, 70)` становится левым ребёнком `(8, 90)`; `return b` возвращает новый корень `(8, 90)`.

Результат:

```text
                  (8, 90)
                 /       \\
            (3, 70)     (10, 30)
            /     \\
        (1, 40)  (5, 60)
                       \\
                      (7, 50)
```

`merge` выбирает корень с большим приоритетом, поэтому сохраняет heap-свойство. Предусловие о диапазонах ключей сохраняет BST-свойство.

Ключевой инвариант: `merge` корректен только при разделённых диапазонах ключей. В каждой операции после смены ребёнка вызывается `update`.

### 2.3. Поиск, вставка и удаление

- **Поиск:** как в обычном BST — сравниваем ключ и спускаемся влево или вправо.
- **Вставка через split:** делим дерево по новому ключу и соединяем `left + new_node + right` с помощью `merge`.
- **Удаление:** находим узел и заменяем его `merge(left, right)`.

#### Пошаговый пример `add`

Вставим узел `(9, 88)` в дерево. `add` находится в `code/add.py`; для него `split` возвращает ключи `<= k` и `> k`. Так как ключа 9 в дереве ещё нет, части будут строго `< 9` и `> 9`.

```text
До вставки:
                 (8, 95)
                /       \\
          (3, 72)       (12, 81)
          /    \\          /
      (1, 40) (6, 58)  (10, 33)
```

1. **Разрезаем дерево:** `left, right = split(root, 9)`. Получаем `left` с ключами `< 9` и `right` с ключами `> 9`. Узел 8 остаётся в `left`, а узлы 10 и 12 — в `right`.
2. **Присоединяем новый узел:** `merge(left, node)` сравнивает `(8, 95)` и `(9, 88)`. У 8 приоритет выше, поэтому 8 остаётся корнем, а `(9, 88)` становится его правым потомком.
3. **Возвращаем правую часть:** `merge(полученное_дерево, right)` сначала оставляет корнем `(8, 95)`, затем сравнивает `(9, 88)` и `(12, 81)`. Узел 9 имеет больший приоритет, поэтому становится правым ребёнком 8, а 12 — его правым ребёнком.

После `root = add(root, Node(9, 88))` получится:

```text
                 (8, 95)
                /       \\
          (3, 72)        (9, 88)
          /    \\              \\
      (1, 40) (6, 58)          (12, 81)
                               /
                           (10, 33)
```

Функция `add` возвращает новый корень, поэтому результат нужно присвоить обратно в `root`. В примере предполагается, что ключа 9 ещё нет.

В файле-примере хранится **множество без дубликатов**. Перед вставкой `contains` проверяет наличие ключа. Для мультимножества обычно хранят в узле `count` одинаковых ключей и включают его в `size` и сумму.

#### Пошаговый пример `delete`

Удалим ключ `8` из дерева. Функция находится в `code/delete.py` и, найдя узел, объединяет его левое и правое поддеревья:

```text
До:
                 (8, 95)
                /       \\
          (3, 72)       (12, 81)
          /    \\          /
      (1, 40) (6, 58)  (10, 33)
```

1. `delete(root, 8)` сравнивает `8` с ключом корня. Они равны, поэтому выполняется `return merge(a.left, a.right)`.
2. `merge` сравнивает корни поддеревьев: `(3, 72)` и `(12, 81)`. Приоритет 81 выше, поэтому `(12, 81)` станет корнем объединения. Вызывается `merge((3, 72), (10, 33))`.
3. У `(3, 72)` приоритет выше, чем у `(10, 33)`, поэтому `(3, 72)` остаётся корнем. Его правое поддерево `(6, 58)` объединяется с `(10, 33)`.
4. Приоритет `(6, 58)` выше, поэтому он становится правым ребёнком `(3, 72)`, а `(10, 33)` — правым ребёнком `(6, 58)`.
5. Объединённое поддерево возвращается и становится левым ребёнком `(12, 81)`. Новый корень нужно сохранить: `root = delete(root, 8)`.

Результат:

```text
                 (12, 81)
                 /
           (3, 72)
           /    \\
       (1, 40) (6, 58)
                      \\
                     (10, 33)
```

Узел `(8, 95)` удалён, остальные узлы сохранены. `merge` восстановил BST-порядок по `x` и max-heap-порядок по `y`.

### 2.4. Ранг, k-й элемент и запросы на отрезке

Если у узлов хранится `size`, можно найти `k`-й ключ за O(log n): сравнить `k` с размером левого поддерева. Ранг ключа — сколько ключей строго меньше него — находится обычным спуском по BST.

Код функции сохранён в `themes/treap/code/kth.py`. Здесь `k` — индекс с нуля: `k = 0` означает минимальный ключ. Узлы хранят ключ в `x`, а размер поддерева — в `size`.

```python
def size(a):
    return a.size if a is not None else 0


def kth(a, k):
    if a is None or k < 0 or k >= a.size:
        raise IndexError("k вне диапазона")

    left_size = size(a.left)
    if k < left_size:
        return kth(a.left, k)
    if k == left_size:
        return a.x
    return kth(a.right, k - left_size - 1)
```

#### Пошаговый пример поиска `k = 5`

Рассмотрим дерево, чьи ключи при симметричном обходе дают `[1, 3, 6, 8, 10, 12]`. Ищем элемент с индексом 5 — последний в этом порядке:

```text
              (8), size=6
             /           \\
       (3), size=3       (12), size=2
       /      \\          /
     (1)      (6)       (10)
```

1. В узле `8` размер левого поддерева равен 3. Так как `k = 5 > 3`, идём вправо. Пропускаем левое поддерево и сам узел: новый индекс `k = 5 - 3 - 1 = 1`.
2. В узле `12` размер левого поддерева равен 1. Теперь `k = 1`, значит мы нашли текущий узел и возвращаем `12`.

При переходе вправо индекс уменьшается на `left_size + 1`; при переходе влево остаётся прежним. Поэтому каждый шаг сохраняет индекс относительно текущего поддерева.

С агрегатом `total` код считает сумму ключей на отрезке `[lo, hi]`. Узлы, чьи поддеревья целиком вне диапазона, обходить не нужно; ожидаемое время O(log n + m), где `m` — число попавших в диапазон узлов (в худшем случае O(n)).

## 3. Неявный Treap

Неявный Treap хранит последовательность, но явных ключей у элементов нет. Код находится в `themes/treap/code/implicit_treap.py`.

### 3.1. Индекс как ключ

Позиция узла определяется количеством элементов слева: `index = size(left)`. Поэтому можно разделить последовательность после первых `k` элементов за ожидаемое O(log n), не перенумеровывая остальные элементы.

Для отрезка `[l, r)` делают два разделения:

```text
a | b | c = split(root, l), затем split(остаток, r - l)
```

Средняя часть `b` — нужный диапазон. После операции части снова объединяются через `merge`.

### 3.2. Разворот отрезка с lazy propagation

Чтобы развернуть диапазон, достаточно поменять местами левого и правого ребёнка его корня и поставить флаг отложенного разворота. Когда спускаемся ниже, `push` передаёт флаг детям. Это позволяет обработать целый диапазон за ожидаемое O(log n), не переворачивая каждый элемент отдельно.

Сумма поддерева не зависит от порядка элементов, поэтому агрегат `total` при развороте не меняется. Для агрегатов, чувствительных к порядку (например, хеш строки), при развороте нужно хранить значения для прямого и обратного порядка.

## 4. Сложность и сравнение

| Операция | Treap по ключу | Неявный Treap |
|---|---:|---:|
| Поиск ключа | O(log n) ожидаемо | — |
| Вставка / удаление | O(log n) ожидаемо | вставка/удаление по позиции O(log n) |
| `split` / `merge` | O(log n) ожидаемо | O(log n) ожидаемо |
| k-й элемент / доступ по индексу | O(log n) ожидаемо | O(log n) ожидаемо |
| Разворот диапазона `[l, r)` | — | O(log n) ожидаемо |
| Память | O(n) | O(n) |

Во всех оценках O(log n) — **ожидаемое** время при случайных независимых приоритетах. Худший случай для отдельной операции — O(n). Реализации в примерах рекурсивные, поэтому патологически высокая форма также может привести к переполнению стека вызовов.

| Структура | Когда удобна |
|---|---|
| Обычный BST | Учебная основа; без балансировки может выродиться |
| AVL / красно-чёрное дерево | Строгая гарантия O(log n), если реализация доступна |
| Treap | Нужны короткие `split`/`merge`, динамические множества или операции над отрезками |
| Fenwick / segment tree | Ключи или позиции фиксированы; нужны агрегаты, но не перестановка последовательности |

Подробнее про BST и AVL: `themes/binary_search_tree/theory/theory.md`.

## 5. Типичные задачи

### 5.1. Операции над множеством

В `ordered_treap.py` показаны вставка, удаление, поиск, сумма диапазона, ранг и поиск k-го элемента. Это полезно, если ключи появляются динамически и заранее сжать координаты нельзя.

Пример: поддерживать множество целых чисел с командами `+ x`, `- x`, `? k` (найти k-й по возрастанию). Для дубликатов заранее выберите модель: множество, счётчик в узле или отдельные пары `(key, уникальный_id)`.

### 5.2. Редактирование последовательности

В `implicit_treap.py` последовательность разворачивается на отрезке и вычисляет сумму элементов диапазона. Та же схема с `split`/`merge` поддерживает вставку и удаление по позиции, перемещение отрезка и циклический сдвиг.

Внимательно договоритесь о границах. В примере все интервалы полуоткрытые `[l, r)`: `l` включён, `r` не включён. Для диапазона с включёнными концами `[l, r]` длина равна `r - l + 1`.

## 6. Частые ошибки

1. **Перепутать приоритет и ключ.** BST-инвариант относится к ключам, heap-инвариант — к приоритетам.
2. **Вызвать `merge` для пересекающихся диапазонов ключей.** Все ключи левого дерева обязаны быть меньше всех ключей правого.
3. **Забыть `update` после изменения ребёнка.** Тогда размеры и агрегаты перестанут соответствовать дереву.
4. **Использовать `split(t, k)` с неверным соглашением.** В сохранённой функции слева `<= k`, справа `> k`.
5. **Считать случайное балансирование строгой гарантией.** Treap имеет ожидаемую сложность O(log n), но худший случай O(n).
6. **Забыть `push` в неявном Treap.** Перед спуском нужно применить отложенный разворот, иначе операции перепутают порядок элементов.
7. **Ошибиться в границах диапазона.** Пример использует полуоткрытые отрезки `[l, r)`.
8. **Использовать случайные приоритеты для равных ключей без правила.** Для множества код игнорирует повтор; для мультимножества храните частоту или добавляйте уникальный идентификатор.

## 7. Шпаргалка

```text
Treap = BST по key + heap по случайному priority
split(t, k) -> ключи <= k | ключи > k
merge(a, b) корректен, если каждый ключ a < каждого ключа b
insert: split + merge(left, new_node, right)
erase: найти узел и заменить merge(left, right)
implicit Treap: индекс узла = size(left)
отрезок [l, r): два split, операция над серединой, затем merge
ожидаемая сложность операций O(log n), худшая O(n)
```

## 8. Вопросы для самопроверки

1. Какие два свойства одновременно выполняет Treap?
2. Что возвращает `split(t, k)` в сохранённой реализации?
3. Почему для `merge(a, b)` недостаточно, чтобы приоритеты были корректны?
4. Как найти узел с индексом `k` в неявном Treap?
5. Почему сложность Treap называют ожидаемой?
6. Для чего нужен `push` при ленивом развороте диапазона?

<details>
<summary>Ответы</summary>

1. BST по ключам и heap по приоритетам.
2. Дерево с ключами `<= k` и дерево с ключами `> k`.
3. Нужно также сохранить BST-порядок: все ключи в `a` должны быть меньше всех ключей в `b`.
4. Сравнивать `k` с `size(left)`: меньше — идти влево, равно — текущий узел, больше — вправо с уменьшением `k` на `size(left) + 1`.
5. При случайных независимых приоритетах высота логарифмическая в среднем; для неудачных приоритетов дерево может выродиться в цепочку.
6. `push` передаёт флаг разворота детям, чтобы дальнейший спуск видел актуальный порядок последовательности.

</details>
