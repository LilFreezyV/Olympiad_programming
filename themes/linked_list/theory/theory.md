## 1. Что такое связный список

**Связный список** — это структура данных, в которой элементы (их называют **узлами**, node) хранятся не подряд в памяти, как в массиве, а **разбросаны произвольно**. Каждый узел содержит:

- **значение** (данные),
- **ссылку на следующий узел** (а в двусвязном списке — ещё и на предыдущий).

```
head
 ↓
[ 5 | •]──▶[ 3 | •]──▶[ 8 | •]──▶[ 1 |None]
```

Массив «знает», где лежит любой элемент, по формуле `начало + i * размер`. Связный список так не умеет: чтобы добраться до третьего элемента, нужно пройти по ссылкам от `head` через первый и второй. Зато **добавить или удалить узел** можно за O(1), если уже есть ссылка на нужное место — не нужно сдвигать остальные элементы, как в массиве.

> **Аналогия.** Массив — это ряд пронумерованных ячеек в камере хранения: адрес любой ячейки известен заранее. Связный список — это цепочка людей, держащихся за руки: чтобы найти пятого человека, нужно пройти всю цепочку от начала, зато вставить нового человека между двумя другими — просто перехватить руки, не переставляя всех остальных.

## 2. Виды связных списков

| Вид | Особенность |
|---|---|
| **Односвязный (singly linked list)** | у узла есть ссылка только на следующий узел |
| **Двусвязный (doubly linked list)** | у узла есть ссылки и на следующий, и на предыдущий узел |
| **Кольцевой (circular linked list)** | последний узел ссылается не на `None`, а обратно на первый |

В этом конспекте подробно разберём односвязный и двусвязный списки — они встречаются чаще всего.

## 3. Узел и односвязный список

### 3.1. Класс узла

```python
class Node:
    def __init__(self, value):
        self.value = value   # хранимые данные
        self.next = None     # ссылка на следующий узел (пока их нет)
```

### 3.2. Односвязный список с головой и хвостом

Чтобы `append` (добавление в конец) работало за O(1), а не O(n), список хранит ссылки сразу на **голову** (`head`) и **хвост** (`tail`).

```python
class SinglyLinkedList:
    def __init__(self):
        self.head = None
        self.tail = None
        self._size = 0

    def __len__(self):
        return self._size

    def __bool__(self):
        return self._size > 0

    # ---------- добавление ----------

    def append(self, value):
        """Добавить в конец: O(1) благодаря ссылке на tail."""
        node = Node(value)
        if self.tail is None:            # список был пуст
            self.head = self.tail = node
        else:
            self.tail.next = node
            self.tail = node
        self._size += 1

    def prepend(self, value):
        """Добавить в начало: O(1)."""
        node = Node(value)
        node.next = self.head
        self.head = node
        if self.tail is None:            # список был пуст
            self.tail = node
        self._size += 1

    def insert_after(self, prev_node, value):
        """Вставить value сразу после узла prev_node: O(1)."""
        if prev_node is None:
            raise ValueError("prev_node не может быть None")
        node = Node(value)
        node.next = prev_node.next
        prev_node.next = node
        if prev_node is self.tail:       # вставили после последнего узла
            self.tail = node
        self._size += 1

    # ---------- удаление ----------

    def remove(self, value):
        """Удалить первый узел со значением value: O(n)."""
        prev, current = None, self.head
        while current is not None:
            if current.value == value:
                if prev is None:               # удаляем head
                    self.head = current.next
                else:
                    prev.next = current.next
                if current is self.tail:        # удаляем tail
                    self.tail = prev
                self._size -= 1
                return True
            prev, current = current, current.next
        return False                            # значение не найдено

    def pop_front(self):
        """Удалить и вернуть значение из начала: O(1)."""
        if self.head is None:
            raise IndexError("pop from empty list")
        value = self.head.value
        self.head = self.head.next
        if self.head is None:               # список опустел
            self.tail = None
        self._size -= 1
        return value

    # ---------- поиск и обход ----------

    def find(self, value):
        """Найти узел со значением value: O(n)."""
        current = self.head
        while current is not None:
            if current.value == value:
                return current
            current = current.next
        return None

    def __iter__(self):
        current = self.head
        while current is not None:
            yield current.value
            current = current.next

    def __repr__(self):
        return " -> ".join(str(v) for v in self)
```

Проверка:

```python
ll = SinglyLinkedList()
ll.append(1)
ll.append(2)
ll.append(3)
ll.prepend(0)
print(ll)              # 0 -> 1 -> 2 -> 3
print(len(ll))          # 4

node = ll.find(1)
ll.insert_after(node, 99)
print(ll)                # 0 -> 1 -> 99 -> 2 -> 3

ll.remove(99)
print(ll)                 # 0 -> 1 -> 2 -> 3
print(ll.pop_front())      # 0
print(ll)                   # 1 -> 2 -> 3
```

### 3.3. Сложность операций односвязного списка

| Операция | Сложность | Комментарий |
|---|---|---|
| `append` (в конец) | O(1) | благодаря ссылке `tail` |
| `prepend` (в начало) | O(1) | просто переставляем `head` |
| `insert_after(node, x)` | O(1) | если узел `node` уже найден |
| доступ по индексу `arr[i]` | O(n) | нет прямого адреса, только обход |
| `find(value)` | O(n) | нужно перебрать список |
| `remove(value)` | O(n) | сначала нужно найти узел |
| `pop_front` | O(1) | голова известна сразу |
| `pop_back` (удалить с конца) | O(n) | в односвязном списке нет ссылки назад, нужно дойти до предпоследнего узла |

Обратите внимание на последнюю строку: несмотря на то что `tail` известен, удалить последний узел за O(1) **нельзя** — нужно найти узел **перед** ним, а для этого — пройти весь список сначала. Эта асимметрия («быстро добавить в конец, но медленно удалить с конца») — характерная черта именно **односвязного** списка. Решается она двусвязным списком.

## 4. Двусвязный список

У каждого узла — ссылки на **соседей с обеих сторон**. Это позволяет удалять с конца, а также идти по списку в обе стороны.

```
None ◀─[•| 5 |•]⇄[•| 3 |•]⇄[•| 8 |•]⇄[•| 1 |•]─▶ None
       head                              tail
```

### 4.1. Класс узла

```python
class DNode:
    def __init__(self, value):
        self.value = value
        self.prev = None
        self.next = None
```

### 4.2. Реализация

```python
class DoublyLinkedList:
    def __init__(self):
        self.head = None
        self.tail = None
        self._size = 0

    def __len__(self):
        return self._size

    def append(self, value):
        """Добавить в конец: O(1)."""
        node = DNode(value)
        if self.tail is None:
            self.head = self.tail = node
        else:
            node.prev = self.tail
            self.tail.next = node
            self.tail = node
        self._size += 1

    def prepend(self, value):
        """Добавить в начало: O(1)."""
        node = DNode(value)
        if self.head is None:
            self.head = self.tail = node
        else:
            node.next = self.head
            self.head.prev = node
            self.head = node
        self._size += 1

    def remove_node(self, node):
        """Удалить конкретный узел: O(1), т.к. известны оба соседа."""
        if node.prev is not None:
            node.prev.next = node.next
        else:
            self.head = node.next          # удаляем head
        if node.next is not None:
            node.next.prev = node.prev
        else:
            self.tail = node.prev           # удаляем tail
        self._size -= 1

    def pop_back(self):
        """Удалить и вернуть значение с конца: O(1) — вот где выигрывает двусвязный список."""
        if self.tail is None:
            raise IndexError("pop from empty list")
        value = self.tail.value
        self.remove_node(self.tail)
        return value

    def __iter__(self):
        current = self.head
        while current is not None:
            yield current.value
            current = current.next

    def __reversed__(self):
        current = self.tail
        while current is not None:
            yield current.value
            current = current.prev

    def __repr__(self):
        return " <-> ".join(str(v) for v in self)


dll = DoublyLinkedList()
for x in [1, 2, 3, 4]:
    dll.append(x)
print(dll)                       # 1 <-> 2 <-> 3 <-> 4
print(list(reversed(dll)))        # [4, 3, 2, 1]
print(dll.pop_back())              # 4, O(1)!
print(dll)                          # 1 <-> 2 <-> 3
```

Главное преимущество перед односвязным списком: **удаление известного узла (в том числе последнего) — всегда O(1)**, потому что не нужно искать соседа отдельным проходом. Цена — каждый узел занимает больше памяти (лишняя ссылка `prev`).

> Именно двусвязный список лежит в основе `collections.deque` в Python (реализован через связанные блоки, что даёт O(1) на вставку/удаление с **обоих** концов) и структуры `OrderedDict` / LRU-кэшей, где нужно быстро переставлять узлы.

## 5. Связный список vs массив (list)

| | Связный список | Динамический массив (`list`) |
|---|---|---|
| Доступ по индексу | O(n) | O(1) |
| Добавление в конец | O(1) | O(1) амортизированно |
| Добавление в начало | O(1) | O(n) |
| Вставка/удаление, если узел/позиция уже найдены | O(1) | O(n) — сдвиг элементов |
| Поиск по значению | O(n) | O(n) |
| Память на элемент | больше (указатели) | меньше (данные подряд) |
| Кэш-локальность | плохая (узлы разбросаны) | хорошая (элементы подряд) |

**На практике** в Python связный список почти никогда не пишут вручную для реальных задач — используют `list` (если нужен доступ по индексу) или `collections.deque` (если нужны быстрые операции на обоих концах, например очередь или стек). Собственную реализацию связного списка изучают ради понимания устройства структур данных и часто просят написать на собеседованиях — там она и пригождается на практике.

```python
from collections import deque

dq = deque([1, 2, 3])
dq.appendleft(0)     # O(1)
dq.append(4)           # O(1)
dq.popleft()             # O(1)
dq.pop()                  # O(1)
print(dq)                  # deque([1, 2, 3, 4])
```

## 6. Типичные задачи на связные списки

### 6.1. Разворот списка (reverse)

Классическая задача: развернуть связный список **на месте**, без создания нового списка.

**Идея:** идём по списку и на каждом шаге разворачиваем ссылку `next` в обратную сторону, попутно запоминая, кто был «предыдущим».

```python
def reverse(head):
    """head — ссылка на первый узел (Node). Возвращает новую голову."""
    prev = None
    current = head
    while current is not None:
        next_node = current.next   # запомнить, куда шли дальше
        current.next = prev        # развернуть ссылку
        prev = current              # сдвинуть prev вперёд
        current = next_node          # сдвинуть current вперёд
    return prev                       # prev — новая голова
```

```
До:    1 -> 2 -> 3 -> None

Шаг 1: None <- 1    2 -> 3 -> None      (prev=1, current=2)
Шаг 2: None <- 1 <- 2    3 -> None      (prev=2, current=3)
Шаг 3: None <- 1 <- 2 <- 3               (prev=3, current=None) ← стоп

После: 3 -> 2 -> 1 -> None
```

Сложность O(n) по времени, O(1) по памяти — не заводим новый список, только переставляем указатели.

### 6.2. Обнаружение цикла (алгоритм «черепаха и заяц»)

Если список кольцевой (последний узел по ошибке или намеренно ссылается на один из предыдущих), обход `while current: current = current.next` зациклится навсегда. Обнаружить цикл помогает **два указателя разной скорости**.

```python
def has_cycle(head):
    """Есть ли цикл в списке? O(n) по времени, O(1) по памяти."""
    slow = fast = head
    while fast is not None and fast.next is not None:
        slow = slow.next            # шаг 1 за раз
        fast = fast.next.next        # шаг 2 за раз
        if slow is fast:               # догнал — есть цикл
            return True
    return False                        # fast дошёл до None — цикла нет
```

**Почему это работает:** если цикла нет, «заяц» (`fast`) рано или поздно дойдёт до `None`, как в обычном линейном списке. Если цикл есть, оба указателя окажутся «внутри» цикла и «заяц», двигаясь вдвое быстрее, неизбежно догонит «черепаху» — расстояние между ними на каждом шаге сокращается ровно на 1 (в рамках цикла).

### 6.3. Найти середину списка за один проход

Тот же приём «медленный/быстрый указатель», но без сравнения на равенство:

```python
def find_middle(head):
    """Вернуть значение среднего узла за один проход."""
    slow = fast = head
    while fast is not None and fast.next is not None:
        slow = slow.next
        fast = fast.next.next
    return slow.value
```

Когда `fast` пройдёт весь список (или почти весь), `slow` пройдёт ровно половину пути — окажется в середине.

### 6.4. Слияние двух отсортированных списков

```python
def merge_sorted(l1, l2):
    """l1, l2 — головы двух отсортированных связных списков."""
    dummy = Node(None)     # фиктивный узел, чтобы не обрабатывать head отдельно
    tail = dummy

    while l1 is not None and l2 is not None:
        if l1.value <= l2.value:
            tail.next = l1
            l1 = l1.next
        else:
            tail.next = l2
            l2 = l2.next
        tail = tail.next

    tail.next = l1 if l1 is not None else l2   # довесить остаток
    return dummy.next                            # реальная голова — после dummy
```

Приём **фиктивного узла (dummy node)** очень распространён: он избавляет от специальной обработки случая «первый узел результата ещё не определён» и упрощает код.

### 6.5. Удаление N-го узла с конца за один проход

```python
def remove_nth_from_end(head, n):
    dummy = Node(None)
    dummy.next = head
    fast = slow = dummy

    for _ in range(n):          # разгоняем fast на n шагов вперёд
        fast = fast.next

    while fast.next is not None:   # теперь двигаем оба, пока fast не дойдёт до конца
        fast = fast.next
        slow = slow.next

    slow.next = slow.next.next     # slow стоит перед удаляемым узлом
    return dummy.next
```

Разница в n шагов между `fast` и `slow` сохраняется на протяжении всего прохода, поэтому когда `fast` доходит до последнего узла, `slow` оказывается ровно перед узлом, который нужно удалить — n-м с конца.

## 7. Частые ошибки

1. **Потерять ссылку на остаток списка.** Самая частая ошибка при развороте или вставке: сначала *сохранить* `next`, а только потом менять ссылку.
   ```python
   # неправильно — current.next сразу перезаписывается, ссылка на остаток теряется
   current.next = prev
   prev = current
   current = current.next   # current.next уже испорчен, это prev, а не старый next!
   ```
2. **Забыть обновить `tail` (или `head`) при удалении крайнего узла.** Если удаляете последний элемент, а `tail` не обновили, следующий `append` присоединится к «мёртвому» узлу и результат исчезнет из списка.
3. **Не обработать пустой список или список из одного элемента.** `head is None` и `head.next is None` — типичные граничные случаи, которые стоит проверять отдельно.
4. **Сравнивать узлы через `==` вместо `is`.** У узлов обычно не переопределён `__eq__`, но если он переопределён (сравнивает по значению), можно случайно спутать «два узла с одинаковым значением» с «один и тот же узел». Для сравнения **тождества** узлов используйте `is`.
5. **Бесконечный цикл при обходе кольцевого списка**, если не проверять его на цикличность отдельно (см. раздел 6.2).
6. **Путать `prepend`/`append` в двусвязном списке и забывать обновлять `prev` у соседа.** В двусвязном списке при каждой вставке/удалении нужно поправить **обе** ссылки — и `next` у одного соседа, и `prev` у другого. Забытая половина — источник трудноуловимых багов.

## 8. Шпаргалка

```python
class Node:
    def __init__(self, value):
        self.value = value
        self.next = None        # + self.prev = None для двусвязного списка

# основные приёмы:
# — фиктивный узел (dummy) упрощает вставку/слияние с самого начала списка
# — два указателя разной скорости (slow/fast) — цикл, середина, n-й с конца
# — при развороте: сохранить next ДО того, как его перезаписать
# — двусвязный список даёт O(1) на удаление ЛЮБОГО известного узла,
#   односвязный — только на удаление head

# для реальных задач на практике:
from collections import deque
dq = deque()       # быстрые операции с обоих концов: O(1)
```

| Нужно | Используйте |
|---|---|
| Быстрый доступ по индексу | `list` |
| Быстрое добавление/удаление с обоих концов | `collections.deque` |
| Понять устройство структур данных / собеседование | связный список вручную |

## 9. Вопросы для самопроверки

1. Почему у односвязного списка `pop_back()` стоит O(n), даже если есть ссылка `tail`?
2. Что случится, если при развороте списка забыть сохранить `next` перед его перезаписью?
3. Как работает алгоритм «черепаха и заяц» и почему «заяц» обязательно догонит «черепаху», если цикл есть?
4. Чем двусвязный список выгоднее односвязного и какой ценой достигается эта выгода?
5. Зачем в задачах вроде слияния списков заводят фиктивный узел (dummy)?

<details>
<summary>Ответы</summary>

1. Чтобы удалить последний узел, нужно поправить ссылку `next` у **предпоследнего** узла (сделать её `None`). В односвязном списке нет ссылки «назад», поэтому предпоследний узел можно найти только полным проходом от головы — O(n).
2. Ссылка на оставшуюся часть списка будет потеряна безвозвратно: `current.next` перезапишется раньше, чем мы успеем перейти по старому значению дальше, и все узлы после текущего «отвалятся».
3. Оба указателя двигаются по кругу внутри цикла, но «заяц» — вдвое быстрее. На каждом шаге расстояние между ними внутри цикла сокращается на 1, значит, рано или поздно (не позже чем за длину цикла шагов) они окажутся в одном узле.
4. Двусвязный список позволяет удалить **любой уже найденный** узел (в том числе последний) за O(1), а также обходить список в обе стороны. Цена — дополнительная ссылка `prev` в каждом узле, то есть больше памяти на хранение.
5. Фиктивный узел устраняет необходимость отдельно обрабатывать случай «результат ещё пуст, первый добавленный элемент становится head». Без него код обычно приходится дублировать: отдельная ветка для первой вставки и отдельная — для всех последующих.

</details>
