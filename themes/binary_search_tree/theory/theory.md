## 1. Что такое двоичное дерево поиска

### 1.1. Двоичное дерево и термины

**Двоичное (бинарное) дерево** — структура из узлов, где у каждого узла не больше **двух детей**: левого и правого.

```
            8          ← корень (root)
          /   \
         3     10
        / \      \
       1   6      14
          / \    /
         4   7  13     ← листья (leaves): 1, 4, 7, 13
```

| Термин | Значение |
|---|---|
| **корень** | верхний узел, у него нет родителя (здесь `8`) |
| **лист** | узел без детей (`1`, `4`, `7`, `13`) |
| **поддерево** узла | сам узел и все его потомки; у `3` левое поддерево — `{1}`, правое — `{6, 4, 7}` |
| **глубина** узла | число рёбер от корня до узла (у `8` — 0, у `6` — 2) |
| **высота** дерева | максимальная глубина листа (здесь 3) |

### 1.2. Свойство дерева поиска

**Двоичное дерево поиска** — двоичное дерево, в котором для **каждого** узла с ключом `x`:

- все ключи в **левом поддереве** меньше `x`;
- все ключи в **правом поддереве** больше `x`.

Важно: условие про **всё поддерево**, а не только про детей. В дереве выше у узла `8` в левом поддереве лежат `3, 1, 6, 4, 7` — все меньше 8, а в правом `10, 14, 13` — все больше.

> **Аналогия.** Игра «угадай число от 1 до 100»: на каждый вопрос «больше или меньше?» вы отбрасываете половину вариантов. BST — это записанная заранее стратегия такой игры: в каждом узле вопрос «искомое меньше `x`?», и ответ говорит, в какое поддерево идти.

### 1.3. Зачем оно нужно

| Структура | Поиск | Вставка | Удаление | Мин / макс | Следующий больший |
|---|---|---|---|---|---|
| неотсортированный массив | O(n) | O(1) | O(n) | O(n) | O(n) |
| отсортированный массив + бинпоиск | O(log n) | **O(n)** | **O(n)** | O(1) | O(log n) |
| куча | O(n) | O(log n) | — | только одно из двух | — |
| множество `set` (хеш-таблица) | O(1) | O(1) | O(1) | O(n) | **нет** |
| **BST** | **O(h)** | **O(h)** | **O(h)** | **O(h)** | **O(h)** |

Здесь `h` — высота дерева. BST — единственная из этих структур, которая быстро делает **всё сразу**: хранит элементы упорядоченно и позволяет вставлять и удалять. Если дерево сбалансировано, `h ≈ log₂ n`, и все операции — O(log n). Если нет — до O(n) (раздел 6).

## 2. Узел и обходы дерева

### 2.1. Узел

```python
class Node:
    def __init__(self, key):
        self.key = key
        self.left = None     # левый ребёнок
        self.right = None    # правый ребёнок
```

Дерево целиком задаётся ссылкой на корень. Пустое дерево — `root = None`.

### 2.2. Обходы

Обойти дерево — значит посетить каждый узел ровно один раз. Три рекурсивных порядка отличаются тем, **когда** посещаем сам узел относительно его поддеревьев:

| Обход | Порядок | Для дерева из раздела 1.1 |
|---|---|---|
| **прямой** (pre-order) | узел → левое → правое | 8 3 1 6 4 7 10 14 13 |
| **симметричный** (in-order) | левое → узел → правое | 1 3 4 6 7 8 10 13 14 |
| **обратный** (post-order) | левое → правое → узел | 1 4 7 6 3 13 14 10 8 |
| **в ширину** (level-order) | по уровням сверху вниз | 8 3 10 1 6 14 4 7 13 |

**Главный факт:** симметричный обход BST выдаёт ключи **в отсортированном порядке**. Сначала всё меньшее (левое поддерево), потом сам узел, потом всё большее.

```python
from collections import deque


def inorder(node, out):
    if node is None:
        return
    inorder(node.left, out)
    out.append(node.key)
    inorder(node.right, out)


def preorder(node, out):
    if node is None:
        return
    out.append(node.key)
    preorder(node.left, out)
    preorder(node.right, out)


def level_order(root):
    out = []
    q = deque([root] if root else [])
    while q:
        node = q.popleft()
        out.append(node.key)
        if node.left:
            q.append(node.left)
        if node.right:
            q.append(node.right)
    return out
```

Обход в ширину — это обычный BFS на очереди (конспект `themes/stack_and_queue/theory/theory.md`, раздел 6.1).

Рекурсивный обход на очень высоком дереве упадёт с `RecursionError` (раздел 6). Без рекурсии симметричный обход пишут на стеке:

```python
def inorder_iterative(root):
    out, stack, node = [], [], root
    while stack or node:
        while node:                 # спускаемся влево до упора, запоминая путь
            stack.append(node)
            node = node.left
        node = stack.pop()          # самый левый ещё не посещённый узел
        out.append(node.key)
        node = node.right           # теперь его правое поддерево
    return out
```

## 3. Основные операции

### 3.1. Поиск

Начинаем с корня: если искомое меньше ключа — идём влево, больше — вправо, равно — нашли. Дошли до `None` — ключа нет.

```
Ищем 7:   8 → (7 < 8) влево → 3 → (7 > 3) вправо → 6 → (7 > 6) вправо → 7 ✓
Ищем 5:   8 → 3 → 6 → (5 < 6) влево → 4 → (5 > 4) вправо → None ✗
```

```python
def search(root, key):
    node = root
    while node is not None:
        if key == node.key:
            return node
        node = node.left if key < node.key else node.right
    return None
```

Каждый шаг спускается на уровень ниже, поэтому шагов не больше высоты: O(h).

### 3.2. Вставка

Ищем ключ, как при поиске. Там, где поиск упёрся в `None`, и есть место нового узла: новый ключ всегда становится **листом**.

```python
def insert(root, key):
    """Вставляет key и возвращает (возможно, новый) корень. Дубликаты не добавляет."""
    new = Node(key)
    if root is None:
        return new
    node = root
    while True:
        if key == node.key:
            return root                     # уже есть
        if key < node.key:
            if node.left is None:
                node.left = new
                return root
            node = node.left
        else:
            if node.right is None:
                node.right = new
                return root
            node = node.right


root = None
for x in [8, 3, 10, 1, 6, 14, 4, 7, 13]:
    root = insert(root, x)

out = []
inorder(root, out)
print(out)                  # [1, 3, 4, 6, 7, 8, 10, 13, 14]
print(level_order(root))    # [8, 3, 10, 1, 6, 14, 4, 7, 13]
```

Функция **возвращает корень**, потому что при вставке в пустое дерево корень появляется впервые. Поэтому пишут `root = insert(root, x)`, а не просто `insert(root, x)`.

**Форма дерева зависит от порядка вставки.** Те же числа, вставленные в другом порядке, дают другое дерево. Вставка по возрастанию `1, 2, 3, …` даёт «палку» высоты `n` (раздел 6).

### 3.3. Минимум и максимум

Минимум — самый **левый** узел (идём влево, пока можно), максимум — самый **правый**.

```python
def tree_min(node):
    while node.left is not None:
        node = node.left
    return node


def tree_max(node):
    while node.right is not None:
        node = node.right
    return node


print(tree_min(root).key, tree_max(root).key)   # 1 14
```

### 3.4. Удаление

Самая хитрая операция. Находим удаляемый узел, дальше три случая:

```
1) Лист — просто убираем.          2) Один ребёнок — ставим          3) Два ребёнка — заменяем ключ на
                                      ребёнка на место узла.            следующий по величине (минимум
                                                                       правого поддерева) и удаляем его.
   удаляем 4:                         удаляем 14:                       удаляем 3:
       6          6                     10         10                       8            8
      / \   →      \                      \   →      \                     / \          / \
     4   7          7                      14         13                  3   ...  →   4   ...
                                          /                             /  \          / \
                                        13                             1    6        1   6
                                                                           / \            \
                                                                          4   7            7
```

Почему в третьем случае подходит минимум правого поддерева (его называют **преемником**, successor)? Он больше всех ключей левого поддерева и меньше всех остальных ключей правого — значит, на месте удалённого узла свойство BST сохранится. А у самого преемника **нет левого ребёнка** (иначе он не был бы минимумом), поэтому его удаление — это случай 1 или 2.

```python
def delete(node, key):
    """Удаляет key из поддерева node и возвращает новый корень этого поддерева."""
    if node is None:
        return None                                 # ключа нет
    if key < node.key:
        node.left = delete(node.left, key)
    elif key > node.key:
        node.right = delete(node.right, key)
    else:
        if node.left is None:                       # случаи 1 и 2
            return node.right
        if node.right is None:
            return node.left
        succ = tree_min(node.right)                 # случай 3
        node.key = succ.key
        node.right = delete(node.right, succ.key)
    return node


root = delete(root, 3)
out = []
inorder(root, out)
print(out)                  # [1, 4, 6, 7, 8, 10, 13, 14]
print(level_order(root))    # [8, 4, 10, 1, 6, 14, 7, 13]
```

Приём «функция возвращает новый корень поддерева, а родитель записывает его в `node.left` / `node.right`» избавляет от возни с указателем на родителя. Он встречается почти во всех операциях с деревьями.

### 3.5. Следующий больший и предыдущий меньший

Частый запрос: **наименьший ключ ≥ x** (lower_bound, «потолок») или **наибольший ключ ≤ x** («пол»). Это то, чего не умеет `set`.

Спускаемся, как при поиске, и запоминаем последний подходящий узел: каждый раз, когда идём **влево**, текущий узел больше `x` и может оказаться ответом.

```python
def ceil_key(root, x):
    """Наименьший ключ >= x или None."""
    ans = None
    node = root
    while node is not None:
        if node.key == x:
            return x
        if x < node.key:
            ans = node.key          # подходит, но, может, найдём меньше — идём влево
            node = node.left
        else:
            node = node.right
    return ans


def floor_key(root, x):
    """Наибольший ключ <= x или None."""
    ans = None
    node = root
    while node is not None:
        if node.key == x:
            return x
        if x > node.key:
            ans = node.key
            node = node.right
        else:
            node = node.left
    return ans


print(ceil_key(root, 5), floor_key(root, 5))     # 6 4
print(ceil_key(root, 15), floor_key(root, 0))    # None None
```

### 3.6. Высота и размер

```python
def height(node):
    """Высота в рёбрах; у пустого дерева -1, у одного узла 0."""
    if node is None:
        return -1
    return 1 + max(height(node.left), height(node.right))


def size(node):
    if node is None:
        return 0
    return 1 + size(node.left) + size(node.right)


print(height(root), size(root))   # 3 8
```

Эти функции обходят всё дерево — O(n). Если размер нужен часто, его хранят в узле (раздел 5).

## 4. Повторяющиеся ключи

Определение выше требует **строгих** неравенств, то есть ключи различны. Если нужны повторы (мультимножество), есть два способа:

1. **Счётчик в узле:** `node.cnt` — сколько раз встречается ключ. Вставка существующего ключа увеличивает `cnt`, удаление — уменьшает, а узел удаляется, только когда `cnt` стал 0. Самый простой и надёжный вариант.
2. **Равные — в одну сторону**, например `key <= node.key` → влево. Работает, но равные ключи разбросаны по дереву, и удалять их неудобно.

```python
class CountNode:
    def __init__(self, key):
        self.key = key
        self.cnt = 1
        self.left = None
        self.right = None


def insert_multi(root, key):
    if root is None:
        return CountNode(key)
    node = root
    while True:
        if key == node.key:
            node.cnt += 1
            return root
        side = "left" if key < node.key else "right"
        child = getattr(node, side)
        if child is None:
            setattr(node, side, CountNode(key))
            return root
        node = child


r = None
for x in [5, 3, 5, 8, 3, 5]:
    r = insert_multi(r, x)
print(r.key, r.cnt, r.left.key, r.left.cnt)   # 5 3 3 2
```

## 5. Порядковые статистики: k-й элемент и ранг

Если в каждом узле хранить **размер его поддерева** `size`, дерево научится отвечать на два новых вопроса за O(h):

- **k-й по величине** элемент (k-я порядковая статистика);
- **ранг** ключа — сколько ключей меньше `x`.

```
             8 (9)
           /       \
        3 (5)       10 (3)        в скобках — size поддерева
       /    \           \
     1 (1)  6 (3)       14 (2)
           /   \        /
         4 (1) 7 (1)  13 (1)
```

**k-й элемент** (нумерация с 0): пусть слева `L = size(left)` узлов.
- `k < L` — ответ в левом поддереве, ищем там `k`-й;
- `k == L` — ответ — сам узел;
- `k > L` — ответ в правом поддереве, ищем там `(k − L − 1)`-й.

```python
class SNode:
    def __init__(self, key):
        self.key = key
        self.size = 1
        self.left = None
        self.right = None


def sz(node):
    return node.size if node else 0


def insert_s(node, key):
    """Вставка с пересчётом размеров (рекурсивная, ключи различны)."""
    if node is None:
        return SNode(key)
    if key < node.key:
        node.left = insert_s(node.left, key)
    elif key > node.key:
        node.right = insert_s(node.right, key)
    node.size = 1 + sz(node.left) + sz(node.right)
    return node


def kth(node, k):
    """k-й по величине ключ, k с нуля."""
    while node is not None:
        left = sz(node.left)
        if k < left:
            node = node.left
        elif k == left:
            return node.key
        else:
            k -= left + 1
            node = node.right
    return None


def rank(node, x):
    """Сколько ключей строго меньше x."""
    r = 0
    while node is not None:
        if x <= node.key:
            node = node.left
        else:
            r += sz(node.left) + 1      # весь левый кусок и сам узел меньше x
            node = node.right
    return r


t = None
for x in [8, 3, 10, 1, 6, 14, 4, 7, 13]:
    t = insert_s(t, x)
print([kth(t, k) for k in range(9)])   # [1, 3, 4, 6, 7, 8, 10, 13, 14]
print(rank(t, 7), rank(t, 9), rank(t, 100))   # 4 6 9
```

С рангом легко посчитать, **сколько ключей в отрезке** `[l, r]`: `rank(t, r + 1) − rank(t, l)` (для целых ключей).

Ни `set`, ни куча, ни отсортированный массив с вставками не умеют этого быстро одновременно со вставкой. Это одна из главных причин писать деревья на олимпиадах.

## 6. Вырождение дерева

### 6.1. Плохой порядок вставки

Вставим ключи по возрастанию:

```
insert 1, 2, 3, 4, 5:

1
 \
  2
   \
    3            высота 4 = n − 1: это, по сути, связный список
     \
      4
       \
        5
```

Все операции становятся O(n), а рекурсивные функции (обходы, `delete`, `height`) на `n ≈ 1000` упадут с `RecursionError`. На олимпиадах тесты с отсортированным вводом есть почти всегда.

```python
import random
import sys

sys.setrecursionlimit(10000)


def build(keys):
    r = None
    for x in keys:
        r = insert(r, x)
    return r


n = 2000
keys = list(range(n))
print(height(build(keys)))          # 1999 — «палка»
random.shuffle(keys)
print(height(build(keys)))          # обычно 20–28
```

### 6.2. Случайный порядок — хорошая высота

Если ключи вставляются в **случайном** порядке, ожидаемая высота — O(log n): на практике примерно в 2 раза больше `log₂ n` (для `n = 2000` получается 20–28 вместо идеальных 10). Отсюда простой приём: если все ключи известны заранее, **перемешайте** их перед вставкой (`random.shuffle`).

Если ключи приходят по одному и порядок задан тестом, перемешать нельзя — нужны **сбалансированные деревья** (раздел 6.3; подробно про АВЛ-дерево — раздел 7, про красно-чёрное — раздел 8).

### 6.3. Сбалансированные деревья (обзор)

Сбалансированные деревья после каждой вставки и удаления **перестраивают** себя (обычно поворотами), чтобы высота всегда была O(log n).

| Дерево | Идея | Где встречается |
|---|---|---|
| **АВЛ-дерево** (AVL) | высоты левого и правого поддеревьев любого узла отличаются не больше чем на 1 — подробно в разделе 7 | учебники, базы данных |
| **Красно-чёрное** | узлы раскрашены, правила раскраски ограничивают высоту `2·log₂ n` — подробно в разделе 8 | `std::set` / `std::map` в C++, `TreeMap` в Java |
| **Декартово дерево** (treap) | у каждого узла случайный приоритет; по ключам — BST, по приоритетам — куча | любимое дерево олимпиадников: короткий код, операции split/merge |
| **Splay-дерево** | каждый найденный узел «вытягивается» в корень | O(log n) амортизированно |
| **B-дерево** | много ключей в узле | файловые системы, базы данных |

В Python **нет** встроенного сбалансированного дерева. Варианты на олимпиаде:
- `bisect.insort` по списку — вставка O(n), но с очень маленькой константой (сдвиг памяти на C); до `n ≈ 10⁵` часто проходит;
- `heapq`, если нужен только минимум;
- своё АВЛ-дерево (раздел 7) или декартово дерево — отдельная тема;
- `SortedList` из библиотеки `sortedcontainers` — удобно, но на большинстве олимпиад сторонних библиотек нет.

## 7. АВЛ-дерево (AVL tree)

**АВЛ-дерево** — первое придуманное сбалансированное дерево поиска. Его описали в 1962 году советские математики Г. М. **А**дельсон-**В**ельский и Е. М. **Л**андис, по первым буквам фамилий оно и названо. Это обычное BST, которое после каждой вставки и удаления **само себя подравнивает**, так что его высота всегда O(log n), в каком бы порядке ни приходили ключи.

> **Аналогия.** Обычное BST — как полка, на которую книги ставят как попало: со временем она перекашивается на один край. АВЛ-дерево — полка с уровнем: как только один край стал заметно ниже другого, книги тут же немного перекладывают, чтобы выровнять. Перекладывать приходится мало и только рядом с местом, куда поставили книгу.

### 7.1. Условие баланса

Для каждого узла посчитаем **баланс** (balance factor):

```
balance(узел) = высота(левое поддерево) − высота(правое поддерево)
```

Высота пустого поддерева считается равной `−1`, у листа — `0`, как в разделе 3.6.

**АВЛ-условие:** у **каждого** узла баланс равен `−1`, `0` или `+1`, то есть высоты левого и правого поддеревьев отличаются не больше чем на 1.

```
   АВЛ-дерево                     НЕ АВЛ-дерево

        8 (+1)                        8 (+2)   ← левое поддерево выше на 2
       /     \                       /    \
      4 (0)   10 (0)                4      10
     / \                           / \
    2   6                         2   6
                                 /
                                1
```

В скобках — баланс узла. Если после вставки или удаления у какого-то узла баланс стал `+2` или `−2`, дерево чинят **поворотами**.

### 7.2. Почему высота O(log n)

Найдём, какое **наименьшее** число узлов `N(h)` может быть в АВЛ-дереве высоты `h`. Самое «худое» такое дерево: у корня одно поддерево высоты `h − 1`, а другое — минимально допустимой высоты `h − 2`, и оба поддерева тоже самые худые:

```
N(h) = N(h − 1) + N(h − 2) + 1,     N(0) = 1,  N(1) = 2
```

| h | 0 | 1 | 2 | 3 | 4 | 5 | 10 | 20 |
|---|---|---|---|---|---|---|---|---|
| N(h) | 1 | 2 | 4 | 7 | 12 | 20 | 232 | 28 656 |

Это почти числа Фибоначчи (`N(h) = F(h + 3) − 1`), а они растут экспоненциально — примерно как `1.618^h`. Значит, при `n` узлах высота не больше ≈ `1.44 · log₂ n`. Для `n = 10⁶` это не больше 28 уровней, а у идеально сбалансированного дерева — 19.

### 7.3. Повороты

**Поворот** — локальная перестройка трёх связей, которая меняет высоты поддеревьев, но **сохраняет свойство BST**.

```
         Правый поворот вокруг y  →
         ←  Левый поворот вокруг x

           y                       x
          / \                     / \
         x   C                   A   y
        / \                         / \
       A   B                       B   C
```

Здесь `A`, `B`, `C` — целые поддеревья (может быть, пустые). В обоих деревьях порядок один и тот же: `A < x < B < y < C`, — симметричный обход не изменился, значит, это всё ещё BST. Поддерево `B` просто «переезжает» от `x` к `y`.

При правом повороте левая часть поднимается на уровень вверх, а правая опускается. Поворот работает за O(1): меняются только три ссылки.

```python
def rotate_right(y):
    x = y.left
    y.left = x.right        # поддерево B переезжает к y
    x.right = y
    update(y)               # сначала y — он теперь ниже x
    update(x)
    return x                # x — новый корень этого поддерева


def rotate_left(x):
    y = x.right
    x.right = y.left        # поддерево B переезжает к x
    y.left = x
    update(x)
    update(y)
    return y
```

`update` пересчитывает высоту (и размер) узла по детям — его код в разделе 7.5. Порядок вызовов важен: высоту нижнего узла нужно пересчитать **до** верхнего.

### 7.4. Четыре случая разбалансировки

Пусть у узла `z` баланс стал `+2` (левое поддерево выше на 2). Смотрим на его левого ребёнка `y`:

**LL — «лево-лево»** (`balance(y) ≥ 0`, перевес снаружи): один **правый** поворот вокруг `z`.

```
вставили 3, 2, 1:

      3 (+2)             2
     /                  / \
    2 (+1)     →       1   3
   /
  1
```

**LR — «лево-право»** (`balance(y) < 0`, перевес внутри): один поворот не поможет — средний ключ останется не на месте. Сначала **левый** поворот вокруг `y` (сводим к случаю LL), потом **правый** вокруг `z`. Это называют **большим (двойным) поворотом**.

```
вставили 3, 1, 2:

      3 (+2)            3                2
     /                 /                / \
    1 (−1)    →       2       →        1   3
     \               /
      2             1
   левый поворот   правый поворот
   вокруг 1        вокруг 3
```

Случаи с перевесом вправо (баланс `−2`) — зеркальные:

| Случай | Баланс `z` | Баланс ребёнка | Что делать |
|---|---|---|---|
| **LL** | `+2` | левый ребёнок `≥ 0` | правый поворот вокруг `z` |
| **LR** | `+2` | левый ребёнок `< 0` | левый поворот вокруг левого ребёнка, затем правый вокруг `z` |
| **RR** | `−2` | правый ребёнок `≤ 0` | левый поворот вокруг `z` |
| **RL** | `−2` | правый ребёнок `> 0` | правый поворот вокруг правого ребёнка, затем левый вокруг `z` |

После поворотов высота поддерева уменьшается на 1, и баланс снова в пределах `[−1, 1]`.

### 7.5. Реализация

В каждом узле храним **высоту** его поддерева (чтобы не пересчитывать её обходом) и заодно **размер** — тогда работают `kth` и `rank` из раздела 5, но уже с гарантированным O(log n).

```python
class AVLNode:
    def __init__(self, key):
        self.key = key
        self.left = None
        self.right = None
        self.h = 0              # высота поддерева: у листа 0
        self.size = 1           # число узлов в поддереве


def h(node):
    return node.h if node else -1


def sz(node):
    return node.size if node else 0


def update(node):
    node.h = 1 + max(h(node.left), h(node.right))
    node.size = 1 + sz(node.left) + sz(node.right)


def balance(node):
    return h(node.left) - h(node.right)


def rebalance(node):
    """Пересчитывает node и, если баланс стал ±2, чинит поворотами. Возвращает новый корень."""
    update(node)
    b = balance(node)
    if b > 1:                                   # перевес влево
        if balance(node.left) < 0:              # LR: сначала сводим к LL
            node.left = rotate_left(node.left)
        return rotate_right(node)               # LL
    if b < -1:                                  # перевес вправо
        if balance(node.right) > 0:             # RL: сначала сводим к RR
            node.right = rotate_right(node.right)
        return rotate_left(node)                # RR
    return node


def avl_insert(node, key):
    if node is None:
        return AVLNode(key)
    if key < node.key:
        node.left = avl_insert(node.left, key)
    elif key > node.key:
        node.right = avl_insert(node.right, key)
    else:
        return node                             # дубликат не добавляем
    return rebalance(node)                      # чиним на обратном пути рекурсии


def avl_delete(node, key):
    if node is None:
        return None
    if key < node.key:
        node.left = avl_delete(node.left, key)
    elif key > node.key:
        node.right = avl_delete(node.right, key)
    else:
        if node.left is None:
            return node.right
        if node.right is None:
            return node.left
        succ = tree_min(node.right)             # tree_min — из раздела 3.3
        node.key = succ.key
        node.right = avl_delete(node.right, succ.key)
    return rebalance(node)
```

Вставка и удаление — это **обычные** вставка и удаление из BST (разделы 3.2 и 3.4) плюс одна строка: на обратном пути рекурсии каждый узел от места изменения до корня вызывает `rebalance`. Поиск, `floor_key`, `ceil_key`, обходы, `kth` и `rank` не меняются вообще — АВЛ-дерево остаётся обычным BST.

Рекурсия здесь безопасна: её глубина равна высоте дерева, а она не больше ≈ `1.44 · log₂ n` (для `n = 10⁵` — не больше 22).

Вставка по возрастанию — худший случай для обычного BST — АВЛ-дереву не страшна:

```python
avl = None
for x in range(1, 100_001):
    avl = avl_insert(avl, x)
print(h(avl), sz(avl))                  # 16 100000 — а обычное BST дало бы высоту 99999

for x in range(1, 100_001, 2):          # удалим все нечётные
    avl = avl_delete(avl, x)
print(h(avl), sz(avl), kth(avl, 0), kth(avl, 49_999))   # 15 50000 2 100000
```

Высота 16 — это минимально возможная высота для 100 000 узлов (`⌊log₂ 100000⌋ = 16`).

**Сколько поворотов нужно.** После **вставки** достаточно не больше одного поворота (одинарного или двойного): он возвращает поддереву прежнюю высоту, и выше по дереву ничего не меняется. После **удаления** повороты могут понадобиться на каждом уровне — до O(log n), но каждый стоит O(1). Итого и вставка, и удаление, и поиск — **O(log n) в худшем случае**.

### 7.6. АВЛ против других сбалансированных деревьев

| | АВЛ-дерево | Красно-чёрное | Декартово (treap) |
|---|---|---|---|
| Высота | ≤ 1.44 · log₂ n | ≤ 2 · log₂ n | O(log n) в среднем |
| Поиск | быстрее всех (дерево ниже) | чуть медленнее | в среднем как у АВЛ |
| Вставка / удаление | больше поворотов | меньше поворотов | split / merge |
| Гарантия | худший случай | худший случай | ожидаемая (случайность) |
| Сложность кода | средняя | высокая | низкая |
| Где | базы данных, где чаще ищут, чем меняют | `std::map`, `std::set`, `TreeMap` | олимпиады |

АВЛ-дерево хорошо подходит, когда поиск выполняется чаще изменений, и его понятно писать с нуля: идея баланса и поворотов проста. На олимпиадах на C++ обычно берут готовый `std::set`, а на Python — своё АВЛ или декартово дерево.

## 8. Красно-чёрное дерево (Red-Black tree)

**Красно-чёрное дерево** (КЧД) — самое распространённое сбалансированное дерево поиска. Его придумал Рудольф Байер в 1972 году, а привычный вид с цветами дали Гибас и Седжвик в 1978-м. На нём построены `std::set` и `std::map` в C++, `TreeMap` и `TreeSet` в Java, многие структуры в ядре Linux.

Идея: вместо точной высоты каждый узел хранит всего **один бит** — цвет, красный или чёрный. Правила раскраски не дают дереву перекоситься сильнее чем в 2 раза. Баланс у КЧД менее строгий, чем у АВЛ, зато при изменениях дерево приходится перестраивать **реже**.

> **Аналогия.** Чёрные узлы — это несущие этажи здания, красные — лёгкие надстройки между ними. Правило: на каждом пути вниз одинаковое число несущих этажей, и две надстройки подряд ставить нельзя. Тогда самый длинный путь не больше чем в 2 раза длиннее самого короткого.

### 8.1. Пять правил

1. Каждый узел либо **красный**, либо **чёрный**.
2. **Корень** — чёрный.
3. Все **пустые листья** (`None`, их ещё называют NIL) считаются чёрными.
4. У **красного** узла оба ребёнка чёрные: **двух красных подряд не бывает**.
5. На любом пути от узла вниз до пустого листа одинаковое число **чёрных** узлов. Это число называют **чёрной высотой** узла.

```
Ч — чёрный, К — красный (пустые листья не нарисованы)

                 13Ч
              /       \
           8К           17К
          /   \        /    \
        1Ч    11Ч    15Ч    25Ч
          \                /   \
          6К             22К   27К
```

Именно такое дерево получится, если вставить ключи `13, 8, 17, 1, 11, 15, 25, 6, 22, 27` алгоритмом из раздела 8.4. Проверим правило 5 для корня: на пути `13 → 8 → 1 → 6 → None` чёрные узлы `13` и `1`, на пути `13 → 17 → 25 → 27 → None` — `13` и `25`. Везде по 2 чёрных узла, не считая пустых листьев, — чёрная высота корня равна 2. Двух красных подряд нигде нет.

### 8.2. Почему высота O(log n)

- По правилу 4 красные узлы не идут подряд, значит, на любом пути красных **не больше половины**. Если чёрная высота корня `bh`, то высота дерева `h ≤ 2 · bh`.
- Поддерево с чёрной высотой `bh` содержит не меньше `2^bh − 1` узлов (это доказывается индукцией: у узла два поддерева с чёрной высотой хотя бы `bh − 1`).
- Значит, `n ≥ 2^(h/2) − 1`, то есть **`h ≤ 2 · log₂(n + 1)`**.

У АВЛ-дерева граница `1.44 · log₂ n` — оно ниже, поэтому поиск в нём чуть быстрее. Зато КЧД дешевле обновлять.

### 8.3. Вставка

Вставляем ключ как в обычное BST и красим новый узел в **красный**. Красный узел не меняет чёрных высот, так что правило 5 сохраняется. Нарушиться может только правило 4: если **родитель** тоже красный. Его чинят, глядя на **дядю** — брата родителя.

Обозначения: `z` — новый (проблемный) узел, `p` — родитель, `g` — дед, `u` — дядя. Пусть `p` — левый ребёнок `g`, правый случай зеркальный.

**Случай 0. Родитель чёрный.** Ничего не нарушено, готово.

**Случай 1. Дядя красный — перекраска.** `p` и `u` становятся чёрными, `g` — красным. Чёрные высоты не изменились, но теперь красный `g` мог оказаться под красным родителем, поэтому продолжаем проверку с `z = g`, на два уровня выше.

```
        gЧ                  gК   ← проблема могла подняться сюда
       /  \                /  \
     pК    uК     →      pЧ    uЧ
     /                   /
   zК                  zК
```

**Случай 2. Дядя чёрный, `z` — «внутренний» внук (треугольник).** `z` — правый ребёнок, а `p` — левый. Левый поворот вокруг `p` превращает треугольник в линию, и получается случай 3 (роли `z` и `p` меняются).

```
        gЧ                  gЧ
       /  \                /  \
     pК    uЧ     →      zК    uЧ
       \                 /
        zК             pК
```

**Случай 3. Дядя чёрный, `z` — «внешний» внук (линия).** Правый поворот вокруг `g`, затем `p` перекрашиваем в чёрный, а `g` — в красный.

```
          gЧ                  pЧ
         /  \                /  \
       pК    uЧ     →      zК    gК
       /                           \
     zК                             uЧ
```

После случая 3 всё исправлено: наверху чёрный `p`, как раньше был чёрный `g`, и чёрные высоты не поменялись.

В конце корень всегда красим в чёрный (правило 2). Поворотов при вставке — **не больше двух** (случай 2 + случай 3), а перекраска в случае 1 поднимается вверх, пока не исправит всё. Итого O(log n).

### 8.4. Реализация вставки

В красно-чёрном дереве удобно хранить у узла ссылку на **родителя**: исправление идёт снизу вверх, от нового узла к корню. Повороты те же, что в АВЛ (раздел 7.3), только нужно аккуратно обновлять ссылки `parent`.

```python
RED, BLACK = "К", "Ч"


class RBNode:
    def __init__(self, key, parent=None):
        self.key = key
        self.color = RED            # новый узел всегда красный
        self.left = None
        self.right = None
        self.parent = parent


def color(node):
    return node.color if node else BLACK      # пустые листья — чёрные (правило 3)


class RBTree:
    def __init__(self):
        self.root = None

    def _replace_child(self, parent, old, new):
        """Подвешивает new на место old у родителя (или делает new корнем)."""
        if parent is None:
            self.root = new
        elif parent.left is old:
            parent.left = new
        else:
            parent.right = new
        if new:
            new.parent = parent

    def _rotate_left(self, x):
        y = x.right
        x.right = y.left
        if y.left:
            y.left.parent = x
        self._replace_child(x.parent, x, y)
        y.left = x
        x.parent = y

    def _rotate_right(self, y):
        x = y.left
        y.left = x.right
        if x.right:
            x.right.parent = y
        self._replace_child(y.parent, y, x)
        x.right = y
        y.parent = x

    def insert(self, key):
        parent, node = None, self.root
        while node:                                 # обычный спуск, как в BST
            if key == node.key:
                return
            parent = node
            node = node.left if key < node.key else node.right
        z = RBNode(key, parent)
        if parent is None:
            self.root = z
        elif key < parent.key:
            parent.left = z
        else:
            parent.right = z
        self._fix_insert(z)

    def _fix_insert(self, z):
        while color(z.parent) == RED:               # случай 0: родитель чёрный — выходим
            p = z.parent
            g = p.parent                            # есть: красный p не может быть корнем
            if p is g.left:
                u = g.right
                if color(u) == RED:                 # случай 1: перекраска
                    p.color = u.color = BLACK
                    g.color = RED
                    z = g
                    continue
                if z is p.right:                    # случай 2: треугольник → линия
                    self._rotate_left(p)
                    z, p = p, z
                p.color, g.color = BLACK, RED       # случай 3: линия
                self._rotate_right(g)
            else:                                   # зеркально: p — правый ребёнок g
                u = g.left
                if color(u) == RED:
                    p.color = u.color = BLACK
                    g.color = RED
                    z = g
                    continue
                if z is p.left:
                    self._rotate_right(p)
                    z, p = p, z
                p.color, g.color = BLACK, RED
                self._rotate_left(g)
        self.root.color = BLACK                     # правило 2


def check_rb(node):
    """Проверяет правила 4 и 5, возвращает чёрную высоту поддерева."""
    if node is None:
        return 1                                    # пустой лист чёрный
    if node.color == RED:
        assert color(node.left) == BLACK and color(node.right) == BLACK, "два красных подряд"
    bl, br = check_rb(node.left), check_rb(node.right)
    assert bl == br, "разная чёрная высота"
    return bl + (node.color == BLACK)
```

Поиск, обходы, `floor_key`, `ceil_key` из разделов 2–3 работают с `RBNode` без изменений: это обычное BST, просто с цветами.

```python
t = RBTree()
for x in [13, 8, 17, 1, 11, 15, 25, 6, 22, 27]:
    t.insert(x)
out = []
inorder(t.root, out)
print(out)                                     # [1, 6, 8, 11, 13, 15, 17, 22, 25, 27]
print(check_rb(t.root) - 1)                    # 2 — чёрная высота корня (без пустых листьев)

t = RBTree()
for x in range(1, 100_001):                    # худший порядок для обычного BST
    t.insert(x)
check_rb(t.root)
print(height(t.root))                          # 30 — меньше границы 2·log2(n+1) ≈ 33.2
```

На вставке по возрастанию КЧД получается выше АВЛ-дерева (30 против 16), но всё равно в пределах `2 · log₂ n`. Для сравнения, обычное BST на тех же данных — «палка» высоты 99 999.

### 8.5. Удаление (идея)

Удаление в КЧД — самая сложная операция из всех в этой теме. Код получается длинным, поэтому разберём только идею.

1. Удаляем узел, как в обычном BST (раздел 3.4). Если у узла два ребёнка, сводим задачу к удалению преемника, у которого не больше одного ребёнка.
2. Если удалённый узел был **красным** — ничего не нарушено: чёрные высоты не изменились.
3. Если он был **чёрным**, на его пути стало на один чёрный узел меньше, и правило 5 нарушено. Если ребёнок, вставший на его место, красный, его просто перекрашивают в чёрный.
4. Иначе на месте удалённого появляется «**дважды чёрный**» узел: ему нужно «отдать» лишний чёрный цвет. Его исправляют по 4 случаям в зависимости от цвета **брата** и его детей: перекрасками и не больше чем **тремя** поворотами, поднимаясь вверх по дереву.

На олимпиаде писать удаление в КЧД с нуля почти никогда не нужно. В C++ есть готовые `std::set` и `std::map`, а в Python, если нужно удаление, проще взять АВЛ-дерево из раздела 7: там удаление — это одна строка `return rebalance(node)`.

### 8.6. КЧД против АВЛ

| | АВЛ-дерево | Красно-чёрное дерево |
|---|---|---|
| Что хранит узел | высоту | 1 бит цвета |
| Высота | ≤ 1.44 · log₂ n | ≤ 2 · log₂ n |
| Поиск | чуть быстрее | чуть медленнее |
| Поворотов при вставке | ≤ 2 | ≤ 2 |
| Поворотов при удалении | до O(log n) | ≤ 3 |
| Сложность кода | проще, особенно удаление | вставка средняя, удаление сложное |
| Где используется | базы данных, поиск важнее изменений | `std::map`, `std::set`, `TreeMap`, ядро Linux |

Оба дерева гарантируют O(log n) на поиск, вставку и удаление **в худшем случае**. Красно-чёрное выбирают для стандартных библиотек, потому что изменения в нём дешевле и предсказуемее.

## 9. Типичные задачи на BST

### 9.1. Проверить, что дерево — BST

**Неправильно** — сравнивать узел только с его детьми:

```
      5
     / \
    3   8          у каждого узла левый ребёнок меньше, правый больше,
       / \         но 4 лежит в ПРАВОМ поддереве 5 и меньше 5 — это не BST
      4   9
```

**Правильно** — передавать вниз допустимый интервал `(lo, hi)`: в левое поддерево узла `x` уходит интервал `(lo, x)`, в правое — `(x, hi)`.

```python
def is_bst(node, lo=float("-inf"), hi=float("inf")):
    if node is None:
        return True
    if not (lo < node.key < hi):
        return False
    return is_bst(node.left, lo, node.key) and is_bst(node.right, node.key, hi)


bad = Node(5)
bad.left, bad.right = Node(3), Node(8)
bad.right.left, bad.right.right = Node(4), Node(9)
print(is_bst(root), is_bst(bad))      # True False
```

Другой способ: сделать симметричный обход и проверить, что последовательность строго возрастает.

### 9.2. Построить сбалансированное BST из отсортированного массива

Корень — средний элемент, левое поддерево строим из левой половины, правое — из правой. Высота получается `⌊log₂ n⌋`, минимально возможная.

```python
def build_balanced(a, lo=0, hi=None):
    if hi is None:
        hi = len(a) - 1
    if lo > hi:
        return None
    mid = (lo + hi) // 2
    node = Node(a[mid])
    node.left = build_balanced(a, lo, mid - 1)
    node.right = build_balanced(a, mid + 1, hi)
    return node


b = build_balanced(list(range(1, 16)))
print(height(b), level_order(b)[:7])   # 3 [8, 4, 12, 2, 6, 10, 14]
```

Это то же самое, что дерево решений бинарного поиска по массиву.

### 9.3. Наименьший общий предок (LCA) в BST

Общий предок узлов `a` и `b`, самый глубокий из возможных. В BST его находит один спуск от корня: пока оба ключа меньше текущего — идём влево, пока оба больше — вправо. Как только они «разошлись» по разные стороны (или один из них равен текущему), текущий узел и есть ответ.

```python
def lca(root, a, b):
    node = root
    while node is not None:
        if a < node.key and b < node.key:
            node = node.left
        elif a > node.key and b > node.key:
            node = node.right
        else:
            return node.key
    return None


t2 = None
for x in [8, 3, 10, 1, 6, 14, 4, 7, 13]:
    t2 = insert(t2, x)
print(lca(t2, 4, 7), lca(t2, 1, 7), lca(t2, 13, 3))   # 6 3 8
```

### 9.4. Сумма ключей на отрезке

Сумма всех ключей из `[l, r]`. Поддеревья, которые целиком вне отрезка, пропускаем, поэтому обходим не всё дерево, а только нужную часть.

```python
def range_sum(node, l, r):
    if node is None:
        return 0
    if node.key < l:
        return range_sum(node.right, l, r)      # весь левый кусок ещё меньше — пропускаем
    if node.key > r:
        return range_sum(node.left, l, r)
    return node.key + range_sum(node.left, l, r) + range_sum(node.right, l, r)


print(range_sum(t2, 4, 10))   # 4 + 6 + 7 + 8 + 10 = 35
```

Если хранить в узлах **сумму поддерева** (как `size` в разделе 5), сумму на отрезке можно считать за O(h) — так же, как ранг.

### 9.5. Восстановить BST по прямому обходу

Дан прямой обход (pre-order) BST с различными ключами. Первый элемент — корень, за ним идут все ключи левого поддерева (они меньше корня), потом правого. Можно вставлять элементы по очереди обычным `insert` — получится ровно исходное дерево. Это O(n·h); есть решение за O(n) с интервалами, как в 7.1.

```python
pre = [8, 3, 1, 6, 4, 7, 10, 14, 13]
t3 = None
for x in pre:
    t3 = insert(t3, x)
out = []
preorder(t3, out)
print(out == pre)        # True
```

## 10. Частые ошибки

1. **`insert(root, x)` вместо `root = insert(root, x)`.** Первый же элемент в пустое дерево потеряется: функция создала корень и вернула его, а результат никуда не записан.
2. **Проверка BST только по детям** (раздел 9.1) — свойство касается **всего** поддерева.
3. **Удаление узла с двумя детьми** простым «выкидыванием» — теряется одно из поддеревьев. Нужно заменить ключ преемником.
4. **Вставка отсортированных данных** — дерево вырождается в список, O(n) на операцию (раздел 6). Перемешивайте ключи или используйте сбалансированное дерево.
5. **Рекурсия на высоком дереве** — `RecursionError` при глубине около 1000. Поиск и вставку пишите циклом, обходы — со стеком, либо увеличивайте `sys.setrecursionlimit` (помогает только до нескольких тысяч).
6. **Не обновить `size` / сумму** в узлах на пути после вставки или удаления — все порядковые запросы начнут врать.
7. **Дубликаты без договорённости** — одни функции отправляют равные влево, другие вправо, и поиск их не находит. Выберите один способ (лучше счётчик, раздел 4).
8. **АВЛ: не пересчитать высоту после поворота** или пересчитать в неправильном порядке. Сначала `update` узла, который оказался **ниже**, потом нового корня поддерева.
9. **АВЛ: забыть, что поворот меняет корень поддерева.** `rotate_right(node)` возвращает новый корень, и его нужно записать родителю: `node.left = rotate_left(node.left)`, `return rotate_right(node)`.
10. **АВЛ: путать случаи LL и LR.** Направление второго поворота определяет баланс **ребёнка**: если перевес «внутри» (LR, RL), нужен двойной поворот.
11. **КЧД: забыть обновить `parent`** при повороте — у трёх узлов: у поднятого, у опущенного и у поддерева, которое переехало. Дальше `_fix_insert` пойдёт по неверным ссылкам.
12. **КЧД: проверять цвет `None`** через `node.color` — упадёт с `AttributeError`. Пустые листья — чёрные, проверяйте через функцию `color(node)`.
13. **КЧД: забыть перекрасить корень в чёрный** в конце вставки — после перекраски (случай 1) корень может стать красным.

## 11. Шпаргалка

```python
class Node:
    def __init__(self, key):
        self.key, self.left, self.right = key, None, None

# поиск / вставка: идём влево, если key < node.key, иначе вправо — O(h)
# вставка всегда создаёт ЛИСТ; root = insert(root, x)
# минимум — самый левый узел, максимум — самый правый
# удаление: лист → убрать; один ребёнок → поднять его;
#           два ребёнка → ключ := минимум правого поддерева, удалить его там
# симметричный обход (левое, узел, правое) = ключи по возрастанию
# size в узлах → k-й элемент и ранг за O(h)
# проверка BST: интервал (lo, hi), а не сравнение с детьми
# отсортированный ввод → «палка»; ключи известны заранее → random.shuffle

# АВЛ: в узле храним h (у листа 0, у None -1) и size; баланс = h(left) - h(right) ∈ {-1, 0, 1}
# вставка / удаление как в BST, но на обратном пути: return rebalance(node)
# баланс +2: левый ребёнок < 0 → сначала rotate_left(ребёнок) (LR); затем rotate_right(node)
# баланс -2: зеркально; высота ≤ 1.44·log2 n

# КЧД: корень и None чёрные; два красных подряд нельзя; на всех путях вниз поровну чёрных
# вставка: новый узел красный; пока родитель красный, смотрим на дядю:
#   дядя красный → перекрасить p, u в чёрный, g в красный, подняться к g
#   дядя чёрный: треугольник → поворот вокруг p; линия → поворот вокруг g, p := Ч, g := К
# в конце root.color = Ч; высота ≤ 2·log2(n + 1)
```

| Операция | Средний случай (случайное дерево) | Худший случай (палка) | АВЛ / КЧД (худший случай) |
|---|---|---|---|
| поиск, вставка, удаление | O(log n) | O(n) | O(log n) |
| минимум, максимум | O(log n) | O(n) | O(log n) |
| floor / ceil | O(log n) | O(n) | O(log n) |
| k-й элемент, ранг (с `size`) | O(log n) | O(n) | O(log n) |
| обход всего дерева | O(n) | O(n) | O(n) |

## 12. Вопросы для самопроверки

1. Ключи вставлены в порядке `5, 2, 8, 1, 4, 7, 9, 3`. Нарисуйте дерево. Какая у него высота?
2. Какой обход BST выдаёт ключи по возрастанию? Почему?
3. Из дерева вопроса 1 удаляют корень `5`. Какой ключ окажется в корне?
4. Почему у преемника (минимума правого поддерева) нет левого ребёнка?
5. Почему дерево из 10⁵ элементов, вставленных по возрастанию, плохо и как этого избежать, если все ключи известны заранее?
6. В каждом узле хранится размер поддерева. Как найти медиану дерева из `n` элементов?
7. В пустое АВЛ-дерево вставили `10, 20, 30, 25, 28`. Какие повороты выполнились и как выглядит дерево?
8. Почему в АВЛ-дереве рекурсивные вставка и удаление безопасны, а в обычном BST — нет?
9. Каким может быть наименьшее число узлов в АВЛ-дереве высоты 4?
10. Почему новый узел в красно-чёрном дереве красят в **красный**, а не в чёрный?
11. Может ли красно-чёрное дерево состоять только из чёрных узлов? А только из красных?

1. ```
          5
        /   \
       2     8
      / \   / \
     1   4 7   9
        /
       3
   ```
   Высота **3** (путь `5 → 2 → 4 → 3`).
2. **Симметричный** (левое → узел → правое): все ключи левого поддерева меньше узла и выводятся раньше него, все ключи правого — больше и выводятся позже. По индукции так упорядочено всё дерево.
3. **7** — минимум правого поддерева `{8, 7, 9}`. Ключ корня заменяется на 7, а узел `7` (лист) удаляется.
4. Если бы у него был левый ребёнок, этот ребёнок был бы меньше и лежал бы в том же правом поддереве — тогда преемник не был бы минимумом.
5. Получится «палка» высоты `10⁵ − 1`: каждая операция O(n), всё вместе O(n²) ≈ 10¹⁰, а рекурсивные функции упадут. Если ключи известны заранее — перемешать их (`random.shuffle`) перед вставкой или сразу построить сбалансированное дерево по отсортированному массиву (раздел 9.2).
6. `kth(root, n // 2)` (нумерация с 0) — за O(h). Для чётного `n` вторая медиана — `kth(root, n // 2 - 1)`.
7. `10, 20, 30` — случай **RR** у узла 10: левый поворот, корень `20`. Затем `25` встаёт левым ребёнком `30`, баланс в норме. `28` встаёт правым ребёнком `25`: у `30` баланс `+2`, а у его левого ребёнка `25` баланс `−1` — случай **LR**: левый поворот вокруг `25`, правый вокруг `30`. Итог:
   ```
         20
        /  \n      10    28
           /  \n         25    30
   ```
8. Глубина рекурсии равна высоте дерева. У АВЛ-дерева она не больше ≈ `1.44 · log₂ n` (десятки уровней), а у обычного BST может дойти до `n` и упасть с `RecursionError`.
9. **12**: `N(4) = N(3) + N(2) + 1 = 7 + 4 + 1` (раздел 7.2).
10. Чёрный узел увеличил бы чёрную высоту на своём пути — сломалось бы правило 5 сразу для всего дерева, и починить это трудно. Красный узел чёрных высот не меняет, а возможное нарушение «два красных подряд» — локальное, его чинят перекраской и поворотами рядом с новым узлом.
11. Только из чёрных — **да**, если дерево идеально сбалансировано: все пути до пустых листьев одной длины (например, один узел или полное дерево из 3, 7, 15 … узлов). Только из красных — **нет**: корень обязан быть чёрным (правило 2), а у красного узла не может быть красного ребёнка.
