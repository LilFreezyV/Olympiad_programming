## 1. Зачем нужны классы

До сих пор данные хранились в отдельных переменных и списках, а функции работали с ними «снаружи». Когда структура данных становится сложнее (стек, очередь, связный список, куча), удобно **упаковать данные и операции над ними вместе**. Для этого и нужен **класс**.

- **Класс** — это «чертёж»: описание того, какие данные хранит объект и что с ними можно делать.
- **Объект (экземпляр)** — конкретная «вещь», сделанная по чертежу. Объектов одного класса может быть сколько угодно, и у каждого свои данные.

> **Аналогия.** Класс — это форма для печенья, а объекты — сами печенья. Форма одна, печенья разные: одно можно посыпать сахаром, другое — корицей, и это никак не влияет на остальные.

Все структуры данных в следующих темах (связный список, стек, очередь, дек, куча) написаны именно на классах, поэтому эта тема — фундамент.

## 2. Первый класс

Пример с занятия (`code/classes.py`):

```python
class MyClass:
    def __init__(self):
        self.x = 0
        self.y = 0

    def add(self):
        self.x = self.x + 1


z = MyClass()       # создаём объект
z.x = 2             # меняем поле
z.x = z.y + 4       # z.x = 0 + 4 = 4
z.add()             # z.x = 5
print(z.x)          # 5
```

Разберём по частям:

| Часть | Что это |
|---|---|
| `class MyClass:` | объявление класса. Имена классов принято писать `СловамиСЗаглавной` (CapWords) |
| `def __init__(self):` | **конструктор** — вызывается автоматически при создании объекта `MyClass()` |
| `self.x = 0` | создаём **поле (атрибут)** `x` у этого конкретного объекта |
| `def add(self):` | **метод** — функция, которая живёт внутри класса и работает с объектом |
| `z = MyClass()` | создаём **новый объект** и кладём ссылку на него в переменную `z` |
| `z.x`, `z.add()` | обращение к полю и вызов метода через точку |

Скобки после имени класса в объявлении (`class MyClass():`) не обязательны — `class MyClass:` означает то же самое.

## 3. Что такое `self`

`self` — это ссылка на **тот объект, у которого вызвали метод**.

```python
a = MyClass()
b = MyClass()

a.add()     # внутри add: self — это a
b.add()     # внутри add: self — это b
b.add()

print(a.x, b.x)   # 1 2 — у каждого объекта свои поля
```

Запись `a.add()` Python на самом деле превращает в `MyClass.add(a)`. Поэтому первым параметром каждого метода всегда идёт `self`, хотя при вызове его не передают.

Частая ошибка — забыть `self.` перед полем:

```python
class Counter:
    def __init__(self):
        self.count = 0

    def inc(self):
        count = self.count + 1    # ОШИБКА: создали локальную переменную, поле не изменилось
        # правильно: self.count = self.count + 1
```

## 4. Конструктор с параметрами

Конструктор может принимать аргументы — так удобно сразу задать начальные значения:

```python
class Node:
    def __init__(self, x):
        self.x = x          # значение
        self.next = None    # ссылка на следующий узел (пока никуда)


n = Node(5)
print(n.x, n.next)          # 5 None
```

Именно так устроен узел во всех «цепочечных» структурах: связном списке, стеке и очереди на ссылках, деке.

## 5. Класс-обёртка: стек поверх списка

Пример с занятия (`code/my_stack.py`) — класс, который прячет внутри обычный список и даёт наружу только операции стека:

```python
class MyStack:
    def __init__(self):
        self.a = []

    def push(self, x):
        self.a.append(x)

    def pop(self):
        r = self.a[-1]
        self.a.pop()
        return r


s = MyStack()
s.push(2)
s.push(3)
print(s.pop())      # 3
print(s.pop())      # 2
```

Зачем обёртка, если есть просто `list`? Она **ограничивает интерфейс**: у объекта `MyStack` нет `insert`, срезов или доступа по индексу — только `push` и `pop`. Код, который использует стек, не сможет случайно «сломать» его, вставив элемент в середину. Это называется **инкапсуляция**.

Метод `pop` можно записать короче: `list.pop()` сам возвращает удалённый элемент.

```python
    def pop(self):
        return self.a.pop()
```

Подробнее про стек — в конспекте `themes/stack_and_queue/theory/theory.md`.

## 6. Переменные хранят ссылки на объекты

Это **самое важное** в теме, без этого не понять связные структуры.

Переменная в Python не «содержит» объект, а **указывает** на него. Присваивание `b = a` не копирует объект — теперь две переменные указывают на **один и тот же** объект.

```python
a = Node(1)
b = a           # b указывает туда же, куда a
b.x = 100
print(a.x)      # 100 — это один и тот же объект!
```

```
a ──┐
    ├──▶ [ x=100 | next=None ]
b ──┘
```

Поле объекта тоже может хранить ссылку на **другой объект**. Пример с занятия:

```python
class My2Class:
    def __init__(self):
        self.x = 0
        self.y = 0
        self.p = None       # ссылка на другой объект (пока ни на что)


z = My2Class()
z2 = My2Class()
z2.p = z          # поле p объекта z2 указывает на объект z
z2.p.x = 3        # меняем поле x у объекта z через z2
print(z.x)        # 3
```

### 6.1. Цепочка объектов — это и есть связный список

Если у каждого объекта есть поле-ссылка на следующий, из них можно собрать цепочку (пример из `code/my_stack.py`):

```python
class MyClass:
    def __init__(self, x):
        self.x = x
        self.p = None


z = MyClass(4)
z2 = MyClass(3)
z3 = MyClass(2)
z4 = MyClass(1)
z.p = z2
z2.p = z3
z3.p = z4

print(z.p.p.p.x)    # 1  — три шага по ссылкам от z
print(z.p.x)        # 3
```

```
z ──▶ [4 | •]──▶[3 | •]──▶[2 | •]──▶[1 | None]
```

Цепочку можно строить в цикле и обходить, «шагая» по ссылкам, пока не дойдём до `None`:

```python
head = MyClass(0)       # запоминаем начало цепочки
z = head
for i in range(1, 6):
    k = MyClass(i)
    z.p = k             # привязываем новый объект к последнему
    z = k               # последним становится новый

u = head
while u is not None:
    print(u.x, end=" ")  # 0 1 2 3 4 5
    u = u.p
```

Главное — **не потерять начало** (`head`): если бы мы двигали саму переменную `head`, до первых элементов больше нельзя было бы добраться. Подробно — в конспекте `themes/linked_list/theory/theory.md`.

### 6.2. `is` против `==`, и проверка на `None`

- `a == b` — «равны ли **значения**» (для своих классов по умолчанию — то же, что `is`).
- `a is b` — «это **один и тот же** объект?».

Проверять на `None` принято через `is`: `if node is None`, `while u is not None`. Это быстрее и не зависит от того, как в классе определено `==`.

## 7. Поля объекта и поля класса

Поле, созданное через `self.` внутри метода, принадлежит **конкретному объекту**. Поле, записанное прямо в теле класса, — **общее для всех** объектов.

```python
class Pupil:
    school = "Лицей №1"          # поле класса — общее

    def __init__(self, name):
        self.name = name         # поле объекта — у каждого своё


a = Pupil("Аня")
b = Pupil("Боря")
print(a.school, b.school)        # Лицей №1 Лицей №1
Pupil.school = "Гимназия"
print(a.school)                  # Гимназия — поменялось у всех
```

Ловушка — **изменяемое** поле класса:

```python
class BadStack:
    items = []                   # ОДИН список на все объекты!

    def push(self, x):
        self.items.append(x)


s1 = BadStack()
s2 = BadStack()
s1.push(1)
print(s2.items)                  # [1] — «чужой» элемент!
```

Правило: списки, словари и прочие изменяемые поля создавайте в `__init__` через `self.`.

## 8. Специальные методы (dunder-методы)

Методы с двойными подчёркиваниями (`__init__`, `__len__` …) Python вызывает сам в особых ситуациях. Они позволяют своему классу вести себя как встроенные типы.

| Метод | Когда вызывается |
|---|---|
| `__init__(self, ...)` | при создании объекта `Cls(...)` |
| `__len__(self)` | `len(obj)` |
| `__bool__(self)` | `if obj:`, `while obj:` |
| `__repr__(self)` / `__str__(self)` | `print(obj)`, вывод в консоли |
| `__eq__(self, other)` | `obj == other` |
| `__lt__(self, other)` | `obj < other` (нужно для `sorted`, `heapq`) |
| `__iter__(self)` | `for x in obj:` |

Пример — стек, который можно печатать, проверять на пустоту и измерять:

```python
class Stack:
    def __init__(self):
        self.a = []

    def push(self, x):
        self.a.append(x)

    def pop(self):
        return self.a.pop()

    def __len__(self):
        return len(self.a)

    def __bool__(self):
        return len(self.a) > 0

    def __repr__(self):
        return f"Stack({self.a})"


s = Stack()
s.push(1)
s.push(2)
print(s)            # Stack([1, 2])
print(len(s))       # 2
while s:            # работает благодаря __bool__
    s.pop()
print(s)            # Stack([])
```

Так же сделан класс `MinHeap` в `themes/heap/code/`: у него есть `__len__` и `__bool__`.

Пример `__lt__` — объекты можно сортировать:

```python
class Pupil:
    def __init__(self, name, score):
        self.name = name
        self.score = score

    def __lt__(self, other):
        return self.score < other.score

    def __repr__(self):
        return f"{self.name}:{self.score}"


print(sorted([Pupil("Аня", 5), Pupil("Боря", 3), Pupil("Вика", 4)]))
# [Боря:3, Вика:4, Аня:5]
```

## 9. «Приватные» поля и методы

В Python нет настоящих приватных полей, но есть **соглашение**: имя, начинающееся с `_`, означает «внутреннее, снаружи не трогать».

```python
class MinHeap:
    def __init__(self):
        self.heap = []

    def _sift_up(self, i):    # вспомогательный метод, пользователю класса не нужен
        ...

    def push(self, x):        # публичный метод
        ...
```

Так устроен `MinHeap` из темы про кучу: `_parent`, `_swap`, `_sift_up`, `_sift_down` — внутренняя кухня, а `push`, `pop`, `peek` — то, чем пользуются.

## 10. Частые ошибки

1. **Забыть `self` в параметрах метода** — `def push(x):` → при вызове `s.push(1)` будет `TypeError: push() takes 1 positional argument but 2 were given`.
2. **Забыть `self.` перед полем** — `count += 1` вместо `self.count += 1` создаёт локальную переменную (или падает с `UnboundLocalError`).
3. **Создать объект без скобок** — `s = MyStack` кладёт в `s` сам класс, а не объект. Нужно `MyStack()`.
4. **Изменяемое поле класса** вместо поля объекта (раздел 7).
5. **Думать, что `b = a` копирует объект.** Это вторая ссылка на тот же объект (раздел 6).
6. **Сравнивать с `None` через `==`** — работает, но правильно `is None` / `is not None`.
7. **Потерять начало цепочки**, двигая по ней единственную переменную, которая на неё указывала.

## 11. Шпаргалка

```python
class Name:                          # имя класса — CapWords
    shared = 0                       # поле класса (общее)

    def __init__(self, a, b=None):   # конструктор
        self.a = a                   # поле объекта
        self.items = []              # изменяемые поля — только здесь

    def method(self, x):             # метод: первый параметр — self
        self.a += x
        return self.a

    def _helper(self):               # «внутренний» метод
        ...

    def __len__(self): ...           # len(obj)
    def __bool__(self): ...          # if obj:
    def __repr__(self): ...          # print(obj)
    def __lt__(self, other): ...     # obj < other, sorted, heapq


obj = Name(5)                        # создать объект
obj.method(1)                        # вызвать метод
obj.a                                # прочитать поле
node.next is None                    # проверка ссылки на None
```

## 12. Вопросы для самопроверки

1. Что выведет код?
   ```python
   a = MyClass()
   b = a
   a.add()
   b.add()
   print(a.x)
   ```
2. Чем отличается `s = MyStack` от `s = MyStack()`?
3. Почему при обходе цепочки объектов пишут `u = head` и двигают `u`, а не сам `head`?
4. Два объекта класса `BadStack` из раздела 7 «делят» один список. Как это исправить?
5. Какой метод нужно добавить в класс, чтобы работала конструкция `while stack:`?

<details>
<summary>Ответы</summary>

1. **2.** `a` и `b` ссылаются на один и тот же объект, `add` вызвали у него дважды.
2. `MyStack` — это сам класс (чертёж), `MyStack()` — новый объект, созданный по нему.
3. Если двигать `head`, после обхода мы потеряем ссылку на начало цепочки, и первые элементы станут недоступны.
4. Создавать список в конструкторе: `def __init__(self): self.items = []`.
5. `__bool__` (или `__len__` — если `__bool__` нет, Python проверяет, что `len(obj) != 0`).

</details>
