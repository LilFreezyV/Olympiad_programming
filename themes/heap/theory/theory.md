## 1. Что такое куча

**Куча** — это структура данных в виде дерева, в которой выполняется **свойство кучи**:

- **Min-heap (куча минимумов):** значение в любом узле **не больше** значений его потомков. В корне всегда лежит **минимум**.
- **Max-heap (куча максимумов):** значение в любом узле **не меньше** значений его потомков. В корне всегда лежит **максимум**.

Чаще всего используют **двоичную (бинарную) кучу**: у каждого узла не больше двух детей, а само дерево **полное**: все уровни заполнены целиком, кроме, может быть, последнего, который заполняется слева направо.

Пример min-heap:

```
        1
      /   \
     3     2
    / \   /
   7   4 5
```

Обратите внимание: куча **не отсортирована**. Свойство кучи связывает только родителя и детей. Между «братьями» (3 и 2) и между разными ветками порядка нет. Гарантировано лишь одно: наверху минимум.

> **Аналогия.** Куча похожа на иерархию в компании: каждый начальник «главнее» своих подчинённых, но про двух сотрудников из разных отделов ничего сказать нельзя. Зато всегда известно, кто самый главный: он наверху.

### Зачем она нужна

Куча позволяет быстро:

| Операция | Сложность |
|---|---|
| Посмотреть минимум (`peek`) | O(1) |
| Добавить элемент (`push`) | O(log n) |
| Извлечь минимум (`pop`) | O(log n) |
| Построить кучу из массива (`heapify`) | O(n) |

Для сравнения: в отсортированном списке вставка стоит O(n), а в обычном списке поиск минимума стоит O(n). Куча даёт компромисс, который идеально подходит для **очереди с приоритетом**.

## 2. Хранение кучи в массиве

Благодаря тому, что дерево полное, его удобно хранить **в обычном списке без указателей**. Узлы записываются по уровням, слева направо:

```
Дерево:                 Массив:
        1               индекс:  0  1  2  3  4  5
      /   \             значение: 1  3  2  7  4  5
     3     2
    / \   /
   7   4 5
```

Формулы для узла с индексом `i` (индексация с нуля):

| Кто | Индекс |
|---|---|
| Родитель | `(i - 1) // 2` |
| Левый ребёнок | `2 * i + 1` |
| Правый ребёнок | `2 * i + 2` |

Проверим: у элемента `7` (индекс 3) родитель имеет индекс `(3 - 1) // 2 = 1`, это `3`. Верно.
У элемента `2` (индекс 2) левый ребёнок имеет индекс `2 * 2 + 1 = 5`, это `5`. Верно.

Листья начинаются с индекса `n // 2`, поэтому у первых `n // 2` элементов есть хотя бы один ребёнок.

## 3. Основные операции

Все операции сводятся к двум вспомогательным процедурам: **просеиванию вверх** и **просеиванию вниз**.

### 3.1. Просеивание вверх (sift up) и вставка

**Идея:** новый элемент кладём в конец массива (в первое свободное место дерева). Если он меньше родителя, меняем их местами и повторяем, пока элемент не «всплывёт» на своё место.

Пример: вставляем `0` в кучу `[1, 3, 2, 7, 4, 5]`.

```
Шаг 1: добавили в конец          Шаг 2: 0 < 2, меняем           Шаг 3: 0 < 1, меняем
        1                                1                              0
      /   \                            /   \                          /   \
     3     2                          3     0                        3     1
    / \   / \                        / \   / \                      / \   / \
   7   4 5   0                      7   4 5   2                    7   4 5   2

[1,3,2,7,4,5,0]               [1,3,0,7,4,5,2]                 [0,3,1,7,4,5,2]
```

Элемент поднимается максимум на высоту дерева, а высота равна log₂ n. Отсюда **O(log n)**.

### 3.2. Просеивание вниз (sift down) и извлечение минимума

**Идея:** минимум лежит в корне. Забираем его, а на его место ставим **последний** элемент массива. Теперь корень, скорее всего, нарушает свойство кучи, поэтому «топим» его: меняем с **меньшим** из детей, пока он не окажется меньше обоих детей или не станет листом.

Пример: извлекаем минимум из `[1, 3, 2, 7, 4, 5]`.

```
Шаг 1: забрали 1, на его место     Шаг 2: дети 3 и 2, меньший 2,
последний элемент (5)              меняем 5 и 2
        5                                  2
      /   \                              /   \
     3     2                            3     5
    / \                                / \
   7   4                              7   4

[5,3,2,7,4]                         [2,3,5,7,4]   ← готово, вернули 1
```

Почему меняем именно с **меньшим** ребёнком? Потому что он станет родителем для второго ребёнка, и свойство кучи должно сохраниться. Если бы мы подняли 3, то оказалось бы, что 3 стоит над 2, а это нарушение.

Сложность тоже **O(log n)**.

### 3.3. Построение кучи из массива (heapify)

Можно вставить n элементов по одному, это O(n log n). Но есть способ быстрее: пройти по всем **нелистовым** узлам **с конца к началу** и для каждого выполнить просеивание вниз.

```python
for i in range(n // 2 - 1, -1, -1):
    sift_down(i)
```

**Почему это O(n), а не O(n log n)?** Большинство узлов находится внизу дерева, и им почти некуда просеиваться:

- около n/2 узлов — листья, их вообще не трогаем;
- около n/4 узлов опускаются максимум на 1 уровень;
- около n/8 узлов — максимум на 2 уровня;
- и только корень может опуститься на log n уровней.

Сумма n/4·1 + n/8·2 + n/16·3 + … сходится к величине порядка n.

## 4. Собственная реализация min-heap

Написать кучу самому полезно для понимания. В реальном коде обычно используют модуль `heapq` (раздел 5).

```python
class MinHeap:
    def __init__(self, items=None):
        self.data = list(items) if items else []
        self._heapify()

    # ---------- публичные методы ----------

    def push(self, value):
        """Добавить элемент: O(log n)."""
        self.data.append(value)
        self._sift_up(len(self.data) - 1)

    def pop(self):
        """Извлечь и вернуть минимум: O(log n)."""
        if not self.data:
            raise IndexError("pop from empty heap")
        last = self.data.pop()          # забираем последний элемент
        if not self.data:               # он и был единственным
            return last
        minimum = self.data[0]
        self.data[0] = last             # ставим его в корень
        self._sift_down(0)              # и топим вниз
        return minimum

    def peek(self):
        """Посмотреть минимум, не удаляя: O(1)."""
        if not self.data:
            raise IndexError("peek from empty heap")
        return self.data[0]

    def __len__(self):
        return len(self.data)

    def __bool__(self):
        return bool(self.data)

    # ---------- внутренние методы ----------

    def _sift_up(self, i):
        while i > 0:
            parent = (i - 1) // 2
            if self.data[i] < self.data[parent]:
                self.data[i], self.data[parent] = self.data[parent], self.data[i]
                i = parent
            else:
                break

    def _sift_down(self, i):
        n = len(self.data)
        while True:
            smallest = i
            left, right = 2 * i + 1, 2 * i + 2
            if left < n and self.data[left] < self.data[smallest]:
                smallest = left
            if right < n and self.data[right] < self.data[smallest]:
                smallest = right
            if smallest == i:           # оба ребёнка не меньше: всё на месте
                break
            self.data[i], self.data[smallest] = self.data[smallest], self.data[i]
            i = smallest

    def _heapify(self):
        for i in range(len(self.data) // 2 - 1, -1, -1):
            self._sift_down(i)
```

Проверка:

```python
h = MinHeap([5, 7, 9, 1, 3])
h.push(2)
print(h.peek())                          # 1
print([h.pop() for _ in range(len(h))])  # [1, 2, 3, 5, 7, 9]
```

Чтобы превратить её в **max-heap**, достаточно поменять `<` на `>` в `_sift_up` и `_sift_down`.

## 5. Модуль `heapq` — куча из стандартной библиотеки

В Python нет отдельного класса «куча». Модуль `heapq` предоставляет **функции**, которые работают с **обычным списком** и поддерживают в нём свойство **min-heap**.

```python
import heapq
```

### 5.1. Основные функции

| Функция | Что делает | Сложность |
|---|---|---|
| `heapq.heapify(lst)` | превращает список в кучу **на месте** | O(n) |
| `heapq.heappush(heap, x)` | добавляет элемент | O(log n) |
| `heapq.heappop(heap)` | извлекает и возвращает минимум | O(log n) |
| `heap[0]` | минимум без удаления | O(1) |
| `heapq.heappushpop(heap, x)` | сначала push, потом pop (быстрее, чем по отдельности) | O(log n) |
| `heapq.heapreplace(heap, x)` | сначала pop, потом push | O(log n) |
| `heapq.nsmallest(k, it, key=None)` | k наименьших элементов | O(n log k) |
| `heapq.nlargest(k, it, key=None)` | k наибольших элементов | O(n log k) |
| `heapq.merge(*iterables)` | слияние отсортированных последовательностей | O(n log k) |

### 5.2. Базовый пример

```python
import heapq

nums = [5, 7, 9, 1, 3]
heapq.heapify(nums)          # изменяет список на месте, возвращает None!
print(nums)                  # [1, 3, 9, 7, 5]  ← это куча, а не отсортированный список
print(nums[0])               # 1  ← минимум всегда в nums[0]

heapq.heappush(nums, 2)
print(nums)                  # [1, 3, 2, 7, 5, 9]

while nums:
    print(heapq.heappop(nums), end=" ")   # 1 2 3 5 7 9
```

Можно начинать и с пустого списка: пустой список уже является корректной кучей.

```python
heap = []
for x in [4, 1, 8]:
    heapq.heappush(heap, x)
print(heap[0])   # 1
```

### 5.3. `heappushpop` и `heapreplace`: в чём разница

```python
h = [1, 3, 5]
print(heapq.heappushpop(h, 0))   # 0  ← сначала положили 0, он и оказался минимумом
print(h)                         # [1, 3, 5]

h = [1, 3, 5]
print(heapq.heapreplace(h, 0))   # 1  ← сначала достали старый минимум, потом положили 0
print(h)                         # [0, 3, 5]
```

- `heappushpop` может вернуть **только что добавленный** элемент.
- `heapreplace` всегда возвращает элемент, который был в куче **до** вызова (и падает на пустой куче).

### 5.4. `nlargest` и `nsmallest`

```python
data = [15, 3, 42, 8, 23, 4, 16]
print(heapq.nlargest(3, data))    # [42, 23, 16]
print(heapq.nsmallest(3, data))   # [3, 4, 8]

students = [
    {"name": "Аня",  "score": 91},
    {"name": "Борис", "score": 78},
    {"name": "Вера", "score": 95},
    {"name": "Глеб", "score": 84},
]
top2 = heapq.nlargest(2, students, key=lambda s: s["score"])
print([s["name"] for s in top2])  # ['Вера', 'Аня']
```

Когда что использовать:

- k маленькое по сравнению с n → `nlargest` / `nsmallest`;
- k = 1 → просто `max()` / `min()`;
- k близко к n → `sorted(data)[:k]`.

### 5.5. `merge` — слияние отсортированных списков

```python
a = [1, 4, 7]
b = [2, 5, 8]
c = [3, 6, 9]
print(list(heapq.merge(a, b, c)))   # [1, 2, 3, 4, 5, 6, 7, 8, 9]
```

`merge` работает лениво (возвращает итератор), поэтому подходит даже для огромных файлов, которые не помещаются в память.

## 6. Max-heap в Python

`heapq` по умолчанию строит только min-heap. Есть несколько способов получить max-heap.

### Способ 1: хранить числа со знаком минус (классический)

```python
import heapq

nums = [5, 7, 9, 1, 3]
max_heap = [-x for x in nums]
heapq.heapify(max_heap)

print(-max_heap[0])               # 9  ← максимум
print(-heapq.heappop(max_heap))   # 9
print(-max_heap[0])               # 7

heapq.heappush(max_heap, -10)
print(-max_heap[0])               # 10
```

Главное — не забывать ставить минус и при записи, и при чтении.

### Способ 2: функции для max-heap (Python 3.14+)

Начиная с Python 3.14 в `heapq` появились готовые функции для max-heap:

```python
import heapq

nums = [5, 7, 9, 1, 3]
heapq.heapify_max(nums)
print(nums[0])                    # 9
heapq.heappush_max(nums, 10)
print(heapq.heappop_max(nums))    # 10
```

Также есть `heappushpop_max` и `heapreplace_max`. Если код должен работать на более старых версиях Python, используйте способ 1.

### Способ 3: обёртка с обратным сравнением

Подходит для объектов, которые нельзя просто умножить на −1 (например, строк):

```python
import heapq

class Reverse:
    def __init__(self, value):
        self.value = value
    def __lt__(self, other):
        return self.value > other.value   # «меньше» означает «больше»

heap = []
for word in ["груша", "апельсин", "яблоко"]:
    heapq.heappush(heap, Reverse(word))

print(heapq.heappop(heap).value)   # яблоко  ← лексикографически наибольшее
```

## 7. Очередь с приоритетом

Самое частое применение кучи. Элементы кладут в кучу **кортежами** `(приоритет, данные)`. Кортежи сравниваются поэлементно, поэтому куча упорядочивает их по приоритету.

```python
import heapq

tasks = []
heapq.heappush(tasks, (2, "написать отчёт"))
heapq.heappush(tasks, (1, "исправить баг в проде"))
heapq.heappush(tasks, (3, "ответить на письма"))

while tasks:
    priority, task = heapq.heappop(tasks)
    print(priority, task)
# 1 исправить баг в проде
# 2 написать отчёт
# 3 ответить на письма
```

### Проблема одинаковых приоритетов

Если приоритеты совпадают, Python начнёт сравнивать **вторые** элементы кортежей. Для строк это сработает (но порядок будет алфавитным, а не порядком добавления). Для объектов, которые нельзя сравнить, будет ошибка:

```python
heap = []
heapq.heappush(heap, (1, {"task": "A"}))
heapq.heappush(heap, (1, {"task": "B"}))
# TypeError: '<' not supported between instances of 'dict' and 'dict'
```

**Решение:** добавить в кортеж счётчик между приоритетом и данными. Счётчик уникален, поэтому до сравнения данных дело не дойдёт. Заодно при равных приоритетах сохранится порядок добавления (FIFO).

```python
import heapq
import itertools

class PriorityQueue:
    def __init__(self):
        self._heap = []
        self._counter = itertools.count()

    def push(self, item, priority):
        heapq.heappush(self._heap, (priority, next(self._counter), item))

    def pop(self):
        priority, _, item = heapq.heappop(self._heap)
        return item

    def __len__(self):
        return len(self._heap)


pq = PriorityQueue()
pq.push({"task": "A"}, 1)
pq.push({"task": "B"}, 1)
pq.push({"task": "C"}, 0)

while pq:
    print(pq.pop())
# {'task': 'C'}
# {'task': 'A'}
# {'task': 'B'}
```

> **Для многопоточных программ** есть `queue.PriorityQueue` — это потокобезопасная обёртка над той же кучей. В однопоточном коде `heapq` быстрее и проще.

## 8. Типичные задачи на кучу

### 8.1. K наибольших элементов из потока

Держим **min-heap размера k**. В её корне находится наименьший из k лучших, то есть «порог входа». Новый элемент, который больше порога, вытесняет его.

```python
import heapq

def top_k(stream, k):
    heap = []
    for x in stream:
        if len(heap) < k:
            heapq.heappush(heap, x)
        elif x > heap[0]:
            heapq.heapreplace(heap, x)
    return sorted(heap, reverse=True)

print(top_k([5, 1, 9, 3, 7, 2, 8], 3))   # [9, 8, 7]
```

Память O(k), время O(n log k). Работает даже когда данные приходят по одному и не помещаются в память целиком.

### 8.2. Медиана потока чисел (две кучи)

Делим все числа на две половины:

- `low` — меньшая половина, **max-heap** (храним с минусом);
- `high` — большая половина, **min-heap**.

Тогда медиана берётся с вершин этих куч за O(1).

```python
import heapq

class MedianFinder:
    def __init__(self):
        self.low = []    # max-heap через отрицательные числа
        self.high = []   # min-heap

    def add(self, x):
        # 1. кладём в low, затем самый большой из low переносим в high
        heapq.heappush(self.low, -x)
        heapq.heappush(self.high, -heapq.heappop(self.low))
        # 2. выравниваем размеры: low может быть больше high максимум на 1
        if len(self.high) > len(self.low):
            heapq.heappush(self.low, -heapq.heappop(self.high))

    def median(self):
        if len(self.low) > len(self.high):
            return -self.low[0]
        return (-self.low[0] + self.high[0]) / 2


mf = MedianFinder()
for x in [5, 15, 1, 3]:
    mf.add(x)
    print(mf.median())
# 5
# 10.0
# 5
# 4.0
```

### 8.3. Алгоритм Дейкстры (кратчайшие пути)

Куча каждый раз выдаёт ближайшую ещё не обработанную вершину.

```python
import heapq

def dijkstra(graph, start):
    dist = {v: float("inf") for v in graph}
    dist[start] = 0
    heap = [(0, start)]

    while heap:
        d, v = heapq.heappop(heap)
        if d > dist[v]:          # устаревшая запись, уже нашли путь короче
            continue
        for u, w in graph[v]:
            if d + w < dist[u]:
                dist[u] = d + w
                heapq.heappush(heap, (dist[u], u))
    return dist


graph = {
    "A": [("B", 4), ("C", 1)],
    "B": [("D", 1)],
    "C": [("B", 2), ("D", 5)],
    "D": [],
}
print(dijkstra(graph, "A"))   # {'A': 0, 'B': 3, 'C': 1, 'D': 4}
```

Обратите внимание на приём «ленивого удаления»: `heapq` не умеет менять приоритет элемента внутри кучи, поэтому мы просто добавляем новую запись, а устаревшие пропускаем при извлечении.

### 8.4. Пирамидальная сортировка (heapsort)

Самый простой вариант через `heapq`:

```python
import heapq

def heap_sort_simple(items):
    heap = list(items)
    heapq.heapify(heap)
    return [heapq.heappop(heap) for _ in range(len(heap))]

print(heap_sort_simple([4, 10, 3, 5, 1]))   # [1, 3, 4, 5, 10]
```

Классический вариант **на месте** (без дополнительной памяти) использует max-heap:
1. строим max-heap из массива;
2. меняем корень (максимум) с последним элементом — максимум встал на своё место в конце;
3. уменьшаем «рабочую» часть кучи на 1 и просеиваем новый корень вниз;
4. повторяем.

```python
def heap_sort(arr):
    n = len(arr)

    def sift_down(i, size):
        while True:
            largest = i
            left, right = 2 * i + 1, 2 * i + 2
            if left < size and arr[left] > arr[largest]:
                largest = left
            if right < size and arr[right] > arr[largest]:
                largest = right
            if largest == i:
                return
            arr[i], arr[largest] = arr[largest], arr[i]
            i = largest

    for i in range(n // 2 - 1, -1, -1):     # шаг 1: строим max-heap
        sift_down(i, n)
    for end in range(n - 1, 0, -1):         # шаги 2–4
        arr[0], arr[end] = arr[end], arr[0]
        sift_down(0, end)
    return arr

print(heap_sort([4, 10, 3, 5, 1]))   # [1, 3, 4, 5, 10]
```

Свойства heapsort: всегда O(n log n) (в том числе в худшем случае), O(1) дополнительной памяти, но сортировка **неустойчивая** (равные элементы могут поменяться местами). На практике встроенный `sorted()` обычно быстрее.

## 9. Частые ошибки

1. **Считать кучу отсортированным списком.** После `heapify` гарантирован только `heap[0]`. Например, `heap[1]` — не обязательно второй по величине элемент.
2. **Искать максимум в `heap[-1]`.** В min-heap последний элемент — просто какой-то лист, а не максимум.
3. **Писать `nums = heapq.heapify(nums)`.** Функция меняет список на месте и возвращает `None`, так что `nums` превратится в `None`.
4. **Менять список напрямую** (`heap.append(x)`, `heap.sort()`, `heap[i] = ...`) вперемешку с функциями `heapq`. Это ломает свойство кучи. Работайте только через `heappush` / `heappop` и родственные функции.
5. **Кортежи с несравнимыми данными** при равных приоритетах → `TypeError`. Решение — счётчик (раздел 7).
6. **Забыть минус** при чтении из max-heap, построенной через отрицательные числа.
7. **Использовать кучу для поиска произвольного элемента.** Поиск в куче стоит O(n); куча хороша только для работы с минимумом (или максимумом).

## 10. Шпаргалка

```python
import heapq

heap = []                          # пустая куча
heapq.heapify(lst)                 # список → куча, O(n)
heapq.heappush(heap, x)            # добавить, O(log n)
heapq.heappop(heap)                # достать минимум, O(log n)
heap[0]                            # посмотреть минимум, O(1)
heapq.heappushpop(heap, x)         # push + pop
heapq.heapreplace(heap, x)         # pop + push
heapq.nlargest(k, data, key=...)   # k наибольших
heapq.nsmallest(k, data, key=...)  # k наименьших
heapq.merge(a, b, c)               # слить отсортированные

# max-heap: храним -x (или heapq.*_max в Python 3.14+)
# приоритетная очередь: (priority, counter, item)
```

Индексы в массиве: родитель `(i - 1) // 2`, дети `2i + 1` и `2i + 2`.

## 11. Вопросы для самопроверки

1. Является ли массив `[1, 5, 2, 6, 3]` min-кучей?
2. Где в min-куче может находиться максимальный элемент?
3. Почему при просеивании вниз узел меняют именно с **меньшим** из детей?
4. Почему `heapify` работает за O(n), а не за O(n log n)?
5. Как с помощью `heapq` найти 10 самых дорогих товаров из списка в миллион записей? Какая получится сложность?

<details>
<summary>Ответы</summary>

1. **Нет.** У элемента `5` (индекс 1) дети имеют индексы 3 и 4, это `6` и `3`. Так как 3 < 5, свойство кучи нарушено.
2. Только **в листьях**, то есть в индексах от `n // 2` до `n - 1`. У максимума не может быть детей больше него, значит, будь у него дети, они нарушили бы свойство кучи.
3. Меньший ребёнок станет родителем второго ребёнка. Если поднять больший, он окажется над меньшим, и свойство кучи будет нарушено.
4. Большинство узлов находится в нижних уровнях и просеивается на небольшое расстояние; сумма всех перемещений ограничена величиной порядка n.
5. `heapq.nlargest(10, products, key=lambda p: p["price"])`. Сложность O(n log k) = O(n log 10), то есть фактически линейная.
