## 1. Что такое сортировка и зачем она нужна

**Сортировка** — это перестановка элементов массива так, чтобы они шли в заданном порядке: обычно по неубыванию (`a[0] <= a[1] <= ... <= a[n-1]`).

```
До:     [5, 2, 9, 1, 5, 6]
После:  [1, 2, 5, 5, 6, 9]
```

Сама по себе сортировка редко бывает целью задачи. Чаще это **первый шаг**, после которого задача становится простой:

- найти элемент за O(log n) — **бинарный поиск** работает только на отсортированном массиве;
- найти дубликаты — после сортировки одинаковые элементы стоят **рядом**;
- найти две ближайшие точки на прямой — они будут **соседями** в отсортированном массиве;
- жадные алгоритмы («выбрать максимум непересекающихся отрезков») почти всегда начинаются с сортировки.

> **Аналогия.** Сортировка — как разложить книги на полке по алфавиту. Сама по себе это скучная работа, но потом любую книгу находишь за секунды, а две одинаковые сразу бросаются в глаза.

## 2. Важные свойства алгоритмов сортировки

| Свойство | Что значит |
|---|---|
| **Сложность по времени** | сколько операций нужно в худшем / среднем / лучшем случае |
| **Дополнительная память** | сортирует ли алгоритм «на месте» (**in-place**, O(1) доп. памяти) или нужен ещё массив |
| **Устойчивость (stability)** | сохраняют ли **равные** элементы свой исходный относительный порядок |
| **Основан на сравнениях** | использует ли алгоритм только операцию `a < b` |

### 2.1. Устойчивость — на примере

Отсортируем учеников по оценке:

```
Исходно:        (Аня, 5) (Боря, 4) (Вика, 5) (Гоша, 4)

Устойчиво:      (Боря, 4) (Гоша, 4) (Аня, 5) (Вика, 5)   ← Боря остался перед Гошей
Неустойчиво:    (Гоша, 4) (Боря, 4) (Вика, 5) (Аня, 5)   ← порядок равных мог перемешаться
```

Устойчивость важна, когда сортируют **в несколько проходов**: сначала по имени, потом устойчиво по оценке — и внутри одной оценки имена останутся по алфавиту.

### 2.2. Нижняя оценка: быстрее O(n log n) сравнениями нельзя

Любой алгоритм, который узнаёт о данных **только через сравнения**, в худшем случае делает не меньше ~`n log₂ n` сравнений.

Почему: существует `n!` различных перестановок массива, а каждое сравнение даёт ответ «да/нет», то есть делит множество вариантов не больше чем пополам. Чтобы отличить `n!` вариантов, нужно `log₂(n!) ≈ n log₂ n` сравнений.

Обойти эту границу можно только **не сравнивая** элементы — например, сортировкой подсчётом (раздел 8), когда значения — небольшие целые числа.

## 4. Квадратичные сортировки

Они медленные (O(n²)), и на олимпиадах в чистом виде почти не нужны — при `n = 10⁵` это `10¹⁰` операций. Но их идеи встречаются постоянно, а сортировка вставками реально используется внутри быстрых алгоритмов для маленьких кусков.

### 4.1. Сортировка пузырьком (Bubble sort)

Идём по массиву и меняем местами соседей, стоящих в неправильном порядке. После первого прохода **самый большой** элемент «всплывает» в конец, после второго — второй по величине и т. д.

```
[5, 2, 9, 1]
 5>2 → [2, 5, 9, 1]
 5<9 →  ок
 9>1 → [2, 5, 1, 9]     ← 9 на месте
```

```python
def bubble_sort(a):
    n = len(a)
    for i in range(n - 1):
        swapped = False
        for j in range(n - 1 - i):          # последние i элементов уже на месте
            if a[j] > a[j + 1]:
                a[j], a[j + 1] = a[j + 1], a[j]
                swapped = True
        if not swapped:                     # за проход не было обменов — массив отсортирован
            break
```

**Полезный факт:** число обменов в пузырьке равно числу **инверсий** — пар `i < j`, где `a[i] > a[j]`. Каждый обмен соседей убирает ровно одну инверсию.

### 4.2. Сортировка выбором (Selection sort)

На шаге `i` находим минимум среди `a[i:]` и ставим его на позицию `i`.

```python
def selection_sort(a):
    n = len(a)
    for i in range(n - 1):
        m = i
        for j in range(i + 1, n):
            if a[j] < a[m]:
                m = j
        a[i], a[m] = a[m], a[i]
```

Всегда O(n²) сравнений, но **не больше n − 1 обменов** — полезно, если обмен «дорогой».

Неустойчива: `[(5, 'a'), (5, 'b'), (1, 'c')]` → на первом шаге `(5, 'a')` улетает в конец за `(5, 'b')`.

### 4.3. Сортировка вставками (Insertion sort)

Так сортируют карты в руке: берём очередную карту и вставляем её на нужное место среди уже отсортированных слева.

```
[2, 5, 9 | 1, 6]        ← слева отсортировано, берём 1
[2, 5, _, 9, 6]  сдвигаем 9
[2, _, 5, 9, 6]  сдвигаем 5
[_, 2, 5, 9, 6]  сдвигаем 2
[1, 2, 5, 9 | 6]        ← вставили 1
```

```python
def insertion_sort(a):
    for i in range(1, len(a)):
        x = a[i]
        j = i - 1
        while j >= 0 and a[j] > x:      # строго >, чтобы не переставлять равные → устойчивость
            a[j + 1] = a[j]
            j -= 1
        a[j + 1] = x
```

На **почти отсортированном** массиве работает почти за O(n): внутренний цикл сразу останавливается. Поэтому гибридные сортировки (раздел 9) используют её для коротких кусков.

## 5. Сортировка слиянием (Merge sort)

Принцип **«разделяй и властвуй»**:

1. Делим массив пополам.
2. Рекурсивно сортируем каждую половину.
3. **Сливаем** две отсортированные половины в одну.

```
            [5, 2, 9, 1, 6, 3]
           /                  \
     [5, 2, 9]              [1, 6, 3]
     /      \               /      \
   [5]    [2, 9]          [1]    [6, 3]
            ...                    ...
   [2, 5, 9]              [1, 3, 6]
           \                  /
            [1, 2, 3, 5, 6, 9]
```

### 5.1. Слияние двух отсортированных массивов

Два указателя: на каждом шаге берём меньший из двух «первых» элементов.

```python
def merge(left, right):
    result = []
    i = j = 0
    while i < len(left) and j < len(right):
        if left[i] <= right[j]:          # <= (а не <) — сохраняет устойчивость
            result.append(left[i])
            i += 1
        else:
            result.append(right[j])
            j += 1
    result.extend(left[i:])              # один из хвостов пуст,
    result.extend(right[j:])             # второй просто дописываем
    return result


def merge_sort(a):
    if len(a) <= 1:
        return a
    mid = len(a) // 2
    return merge(merge_sort(a[:mid]), merge_sort(a[mid:]))


print(merge_sort([5, 2, 9, 1, 6, 3]))   # [1, 2, 3, 5, 6, 9]
```

Слияние — та же идея, что и в задаче «слить два отсортированных связных списка» из конспекта по linked list.

### 5.2. Почему O(n log n)

- Уровней деления — `log₂ n` (каждый раз делим пополам).
- На каждом уровне суммарно сливаются все `n` элементов — O(n).
- Итого O(n log n) — **всегда**, независимо от входных данных.

Минус — нужна дополнительная память O(n).

### 5.3. Подсчёт инверсий за O(n log n)

Классическая олимпиадная задача: посчитать число пар `i < j`, где `a[i] > a[j]` (например, «сколько обменов сделает пузырёк»). Наивно — O(n²).

Идея: при слиянии, когда берём элемент из **правой** половины, он меньше всех **оставшихся** элементов левой — это `len(left) - i` инверсий разом.

```python
def sort_and_count(a):
    if len(a) <= 1:
        return a, 0
    mid = len(a) // 2
    left, inv_l = sort_and_count(a[:mid])
    right, inv_r = sort_and_count(a[mid:])

    result = []
    inv = inv_l + inv_r
    i = j = 0
    while i < len(left) and j < len(right):
        if left[i] <= right[j]:
            result.append(left[i])
            i += 1
        else:
            result.append(right[j])
            inv += len(left) - i         # right[j] меньше всех left[i:]
            j += 1
    result.extend(left[i:])
    result.extend(right[j:])
    return result, inv


print(sort_and_count([3, 1, 2])[1])        # 2: пары (3,1) и (3,2)
print(sort_and_count([5, 4, 3, 2, 1])[1])  # 10 = 5·4/2
```

## 6. Быстрая сортировка (Quick sort)

Тоже «разделяй и властвуй», но наоборот: вся работа делается **до** рекурсии.

1. Выбираем **опорный элемент** (pivot).
2. Разбиваем массив на части: `< pivot`, `== pivot`, `> pivot`.
3. Рекурсивно сортируем левую и правую части. Средняя уже на месте.

### 6.1. Простая (наглядная) версия

```python
import random

def quick_sort(a):
    if len(a) <= 1:
        return a
    pivot = random.choice(a)
    less    = [x for x in a if x < pivot]
    equal   = [x for x in a if x == pivot]
    greater = [x for x in a if x > pivot]
    return quick_sort(less) + equal + quick_sort(greater)
```

Отлично объясняет идею, но создаёт много новых списков — на практике медленнее встроенной `sorted` в десятки раз.

### 6.2. Версия на месте (разбиение Хоара)

```python
import random

def quick_sort_inplace(a, lo=0, hi=None):
    if hi is None:
        hi = len(a) - 1
    if lo >= hi:
        return
    pivot = a[random.randint(lo, hi)]
    i, j = lo, hi
    while i <= j:
        while a[i] < pivot:
            i += 1
        while a[j] > pivot:
            j -= 1
        if i <= j:
            a[i], a[j] = a[j], a[i]
            i += 1
            j -= 1
    # теперь a[lo..j] <= pivot, a[i..hi] >= pivot
    quick_sort_inplace(a, lo, j)
    quick_sort_inplace(a, i, hi)
```

### 6.3. Почему pivot нужно выбирать случайно

- **Хороший случай:** pivot делит массив примерно пополам → `log n` уровней → O(n log n).
- **Плохой случай:** pivot каждый раз минимум или максимум → части размера `0` и `n − 1` → `n` уровней → **O(n²)**.

Если всегда брать первый элемент, плохой случай — это **уже отсортированный массив**. На олимпиадах такие тесты есть почти всегда (иногда специально «против quicksort»). Случайный pivot делает худший случай крайне маловероятным.

Ещё одна ловушка: массив из **одинаковых** элементов. Разбиение только на `<` и `>=` на нём уходит в O(n²). Трёхчастное разбиение (6.1) и разбиение Хоара (6.2) с этим справляются.

## 7. Пирамидальная сортировка (Heap sort)

Строим из массива кучу за O(n), затем `n` раз достаём максимум (минимум) за O(log n). Итого O(n log n) в худшем случае и O(1) доп. памяти.

Подробный разбор и код — в конспекте по куче: `themes/heap/theory/theory.md`, раздел 8.4. Короткая версия на `heapq`:

```python
import heapq

def heap_sort(a):
    h = a[:]
    heapq.heapify(h)
    return [heapq.heappop(h) for _ in range(len(h))]
```

## 8. Сортировка подсчётом (Counting sort)

Если значения — **целые числа из небольшого диапазона** `[0, k)`, можно вообще не сравнивать: просто посчитать, сколько раз встречается каждое значение.

```
a = [3, 1, 4, 1, 5, 1, 3]

cnt[0]=0  cnt[1]=3  cnt[2]=0  cnt[3]=2  cnt[4]=1  cnt[5]=1

ответ: 1 1 1 3 3 4 5
```

```python
def counting_sort(a, k):
    """Все элементы a — целые числа из [0, k)."""
    cnt = [0] * k
    for x in a:
        cnt[x] += 1
    result = []
    for value in range(k):
        result.extend([value] * cnt[value])
    return result


print(counting_sort([3, 1, 4, 1, 5, 1, 3], 6))   # [1, 1, 1, 3, 3, 4, 5]
```

Сложность **O(n + k)**. Выгодно, когда `k` не намного больше `n`: например, оценки 1–5, возраст 0–150, буквы `a`–`z`. Если значения до `10⁹` — массив `cnt` не поместится в память.

Если значения в диапазоне `[lo, hi]`, храним `cnt[x - lo]`.

### 8.1. Устойчивая версия (для сортировки записей по ключу)

Когда сортируем не числа, а объекты по целому ключу, нужно сохранить сами объекты. Считаем через префиксные суммы, **с какой позиции** начинается каждый ключ:

```python
def counting_sort_by_key(items, key, k):
    cnt = [0] * k
    for it in items:
        cnt[key(it)] += 1
    start = [0] * k                      # start[v] — первая позиция для ключа v
    for v in range(1, k):
        start[v] = start[v - 1] + cnt[v - 1]
    result = [None] * len(items)
    for it in items:                     # идём в исходном порядке → устойчиво
        v = key(it)
        result[start[v]] = it
        start[v] += 1
    return result


pupils = [("Аня", 5), ("Боря", 4), ("Вика", 5), ("Гоша", 4)]
print(counting_sort_by_key(pupils, key=lambda p: p[1], k=6))
# [('Боря', 4), ('Гоша', 4), ('Аня', 5), ('Вика', 5)]
```

На этой идее построена **поразрядная сортировка (radix sort)**: числа сортируют устойчивым подсчётом сначала по последней цифре, потом по предпоследней и т. д.

## 9. Смешанные (гибридные) сортировки

Ни одна из «чистых» сортировок не лучшая во всём:

| Алгоритм | Сильная сторона | Слабая сторона |
|---|---|---|
| Вставками | очень быстрая на **маленьких** и **почти отсортированных** массивах | O(n²) на больших |
| Быстрая | самая быстрая **в среднем**, на месте | худший случай O(n²) |
| Слиянием | всегда O(n log n), устойчивая | нужна память O(n), много мелких вызовов |
| Пирамидальная | всегда O(n log n), на месте | на практике в 2–3 раза медленнее быстрой |

**Гибридная (смешанная) сортировка** комбинирует несколько алгоритмов так, чтобы каждый работал там, где он сильнее всего. Именно такие сортировки встроены во все популярные языки: `sorted` в Python и `std::sort` в C++ — гибриды.

> **Аналогия.** Чтобы добраться в другой город, летят на самолёте, но до аэропорта едут на такси, а от такси до двери идут пешком. Самолёт «асимптотически» быстрее, но на коротких расстояниях выигрывает простой способ.

### 9.1. Почему на маленьких кусках побеждают вставки

Запись O(n log n) скрывает **константу** — сколько реальной работы стоит за каждым шагом. У слияния и быстрой сортировки она большая: рекурсивные вызовы, создание новых списков, вычисление середины. У сортировки вставками константа крошечная: два вложенных цикла и сдвиги соседних элементов.

Поэтому для маленьких `n` (примерно до 16–32) `n²` с маленькой константой оказывается **меньше**, чем `n log n` с большой. Отсюда общий приём почти всех гибридов: **большие куски делим быстрым алгоритмом, а маленькие куски досортировываем вставками**.

### 9.2. Слияние + вставки

Самый простой гибрид. Код — `code/hybrid_merge_insertion.py`.

```python
THRESHOLD = 16

def hybrid_merge_sort(a, threshold=THRESHOLD):
    if len(a) <= threshold:          # маленький кусок — вставками
        a = a[:]
        insertion_sort(a)
        return a
    mid = len(a) // 2                # большой — как обычный merge sort
    return merge(hybrid_merge_sort(a[:mid], threshold),
                 hybrid_merge_sort(a[mid:], threshold))
```

(`insertion_sort` — из раздела 4.3, `merge` — из раздела 5.1.)

Замер на случайном массиве из 50 000 чисел (точные цифры зависят от компьютера):

| Порог | Время |
|---|---|
| 1 (чистый merge sort) | 0.19 с |
| 4 … 32 | 0.155–0.17 с |
| 64 | 0.18 с |
| 256 | 0.35 с |

При пороге 4–32 гибрид работает примерно на 15–20 % быстрее чистого merge sort. А при слишком большом пороге квадратичные вставки снова начинают тормозить. Так же устроен `std::stable_sort` в C++.

### 9.3. Introsort — интроспективная сортировка (`std::sort` в C++)

Introsort придумал Дэвид Мюссер в 1997 году, чтобы получить скорость быстрой сортировки **без** её худшего случая. «Интроспективная» значит «наблюдающая за собой»: алгоритм следит за глубиной своей рекурсии.

1. Сортируем **быстрой сортировкой**. Pivot — медиана из трёх: `a[lo]`, `a[mid]`, `a[hi]`.
2. Если глубина рекурсии превысила `2·log₂ n`, разбиения явно получаются неудачными, и дальше грозит O(n²). Этот кусок досортировываем **пирамидальной** сортировкой: у неё O(n log n) гарантированно и без доп. памяти.
3. Куски длиной ≤ 16 досортировываем **вставками**.

```
                  quicksort
                /           \
         quicksort         quicksort
          /     \             ...
    вставки   глубина > 2·log n?  ──► heap sort для этого куска
   (≤ 16 эл.)
```

Код — `code/introsort.py`. Главная функция:

```python
def _introsort(a, lo, hi, depth):
    if hi - lo + 1 <= SMALL:                    # маленький кусок
        insertion_sort_range(a, lo, hi)
        return
    if depth == 0:                              # рекурсия слишком глубокая
        heap_sort_range(a, lo, hi)
        return
    pivot = a[median_of_three(a, lo, hi)]
    i, j = lo, hi                               # разбиение Хоара (раздел 6.2)
    while i <= j:
        while a[i] < pivot:
            i += 1
        while a[j] > pivot:
            j -= 1
        if i <= j:
            a[i], a[j] = a[j], a[i]
            i += 1
            j -= 1
    _introsort(a, lo, j, depth - 1)
    _introsort(a, i, hi, depth - 1)


def introsort(a):
    if len(a) > 1:
        _introsort(a, 0, len(a) - 1, 2 * int(math.log2(len(a))))
```

**Что это даёт.** В `code/introsort.py` есть опыт: introsort с намеренно **плохим** pivot (всегда первый элемент) на уже отсортированном массиве из 100 000 элементов. Обычная быстрая сортировка с таким pivot при n = 3000 роняет Python (см. `code/quick_sort.py`). Introsort на глубине 32 замечает проблему, один раз переключается на heap sort и спокойно досортировывает массив.

Итог: в среднем introsort так же быстр, как quicksort, а в худшем случае — O(n log n). Поэтому `std::sort` в C++ нельзя «завалить» специально подобранным тестом. Но он **неустойчив**: если нужна устойчивость, в C++ берут `std::stable_sort`.

### 9.4. Timsort — встроенная сортировка Python

Timsort придумал Тим Питерс в 2002 году для Python. Сейчас он также используется в Java (для объектов) и Android. Идея: реальные данные редко бывают совсем случайными, в них часто есть **уже упорядоченные куски**, и их надо использовать, а не ломать.

**Шаг 1. Ищем пробеги (runs)** — максимальные неубывающие или строго убывающие куски. Убывающие разворачиваем.

```
[1 2 5 9 | 8 4 3 | 6 7 7 | 0 ...]
 пробег 4  пробег 3  пробег 3
           ↓ разворот
          [3 4 8]
```

Убывающий пробег разворачивают, только если он **строго** убывающий. Иначе равные элементы поменялись бы местами, и пропала бы устойчивость.

**Шаг 2. Слишком короткие пробеги удлиняем** до `minrun` (от 16 до 32 в нашей версии, от 32 до 64 в CPython) **бинарными вставками**: место для вставки ищем бинпоиском, так сравнений меньше. `minrun` подбирается так, чтобы число пробегов было степенью двойки или чуть меньше — тогда слияния выходят равными.

**Шаг 3. Сливаем пробеги через стек.** Каждый новый пробег кладём на стек и сливаем верхние, пока для трёх верхних длин `A`, `B`, `C` (C — верхний) выполняются правила:

```
A > B + C        B > C
```

Тогда сливаются куски похожей длины (как в обычном merge sort), а стек никогда не бывает длиннее O(log n).

**Шаг 4. Галоп (galloping).** Если при слиянии из одного куска много раз подряд берутся элементы, Timsort переключается на экспоненциальный поиск и переносит их пачкой. В нашей учебной версии этого шага нет.

Код — `code/timsort.py`. Главный цикл:

```python
def timsort(a):
    n = len(a)
    if n < 2:
        return
    minrun = calc_minrun(n)
    runs = []                                   # стек пробегов: (начало, длина)
    lo = 0
    while lo < n:
        hi = count_run(a, lo, n)                # конец пробега, начинающегося в lo
        if hi - lo < minrun:                    # короткий — дополняем вставками
            force = min(lo + minrun, n)
            binary_insertion_sort(a, lo, force, hi)
            hi = force
        runs.append((lo, hi - lo))
        merge_collapse(a, runs)                 # сливаем, пока не выполнены правила стека
        lo = hi
    merge_force_collapse(a, runs)               # в конце сливаем всё оставшееся
```

Замер учебной версии на 100 000 элементах:

| Данные | Пробегов | Время |
|---|---|---|
| случайные | много коротких | 0.34 с |
| почти отсортированные (10 обменов) | 21 | 0.08 с |
| отсортированные по убыванию | 1 | 0.02 с |

На отсортированном (в любую сторону) массиве Timsort находит **один** пробег и заканчивает работу за O(n). Поэтому `sorted()` для уже отсортированных данных почти ничего не стоит.

Начиная с Python 3.11, порядок слияния пробегов в CPython выбирается по более точному правилу **Powersort**, но остальная схема та же.

### 9.5. Что используется в разных языках

| Язык / функция | Алгоритм | Устойчива |
|---|---|---|
| Python `sorted`, `list.sort` | Timsort (с 3.11 — с правилом слияния Powersort) | да |
| C++ `std::sort` | Introsort | нет |
| C++ `std::stable_sort` | слияние + вставки | да |
| Java `Arrays.sort` для `int[]`, `double[]` … | Dual-Pivot Quicksort (быстрая с двумя опорными, тоже гибрид) | нет |
| Java `Arrays.sort` для объектов, `Collections.sort` | Timsort | да |
| Go `sort.Slice`, `slices.Sort` (с 1.19) | pdqsort | нет |

**pdqsort** (pattern-defeating quicksort, 2016) — развитие introsort: он вдобавок распознаёт «узоры» в данных, например уже отсортированные куски или много одинаковых элементов, и обрабатывает их быстрее.

**Вывод для олимпиад:** встроенные сортировки — это гибриды, тщательно настроенные под реальные данные. Свою сортировку писать стоит, только если нужно что-то посчитать по ходу (инверсии) или если значения позволяют обойтись без сравнений (сортировка подсчётом).

## 10. Сортировка в Python на практике

На олимпиаде свою сортировку писать почти никогда не нужно: встроенная (**Timsort** — гибрид слияния и вставок, см. раздел 9.4) работает за O(n log n), устойчива и написана на C, поэтому намного быстрее любой сортировки на чистом Python.

### 10.1. `sorted` и `list.sort`

```python
a = [5, 2, 9, 1]

b = sorted(a)       # новый список, a не меняется; работает с любым итерируемым
a.sort()            # сортирует на месте, возвращает None

a = a.sort()        # ОШИБКА: теперь a == None
```

### 10.2. Обратный порядок и ключ

```python
nums = [5, -2, 9, -10]
sorted(nums, reverse=True)          # [9, 5, -2, -10]
sorted(nums, key=abs)               # [-2, 5, 9, -10] — по модулю

words = ["banana", "Apple", "cherry", "kiwi"]
sorted(words)                       # ['Apple', 'banana', 'cherry', 'kiwi'] — заглавные раньше строчных
sorted(words, key=str.lower)        # без учёта регистра
sorted(words, key=len)              # по длине: ['kiwi', 'Apple', 'banana', 'cherry']
```

`key` вычисляется **один раз** для каждого элемента, а не при каждом сравнении.

### 10.3. Сортировка по нескольким ключам

Кортежи сравниваются **лексикографически**: сначала первые элементы, при равенстве — вторые и т. д. Поэтому ключ-кортеж — стандартный приём.

```python
pupils = [("Вика", 5, 17), ("Аня", 5, 16), ("Боря", 4, 16)]

# по оценке по убыванию, при равенстве — по имени по возрастанию
pupils.sort(key=lambda p: (-p[1], p[0]))
# [('Аня', 5, 16), ('Вика', 5, 17), ('Боря', 4, 16)]
```

Минус работает только для чисел. Для строк «по убыванию» используют **устойчивость** и сортируют несколько раз — от второстепенного ключа к главному:

```python
pupils.sort(key=lambda p: p[0], reverse=True)   # второстепенный: имя по убыванию
pupils.sort(key=lambda p: p[1])                 # главный: оценка по возрастанию
```

### 10.4. Свой компаратор: `cmp_to_key`

Иногда порядок проще описать сравнением двух элементов, чем ключом. Классика: **составить из чисел наибольшее число** (`[3, 30, 34, 5, 9]` → `9534330`). Число `a` должно стоять раньше `b`, если `a + b > b + a` как строки.

```python
from functools import cmp_to_key

def cmp(a, b):
    if a + b > b + a:
        return -1      # a раньше b
    if a + b < b + a:
        return 1       # b раньше a
    return 0

nums = [3, 30, 34, 5, 9]
s = sorted(map(str, nums), key=cmp_to_key(cmp))
print("".join(s))      # 9534330
```

Компаратор возвращает отрицательное число, если `a` должен идти раньше, положительное — если позже, и 0 — если равны.

### 10.5. Индексы в порядке сортировки (argsort)

Часто нужно знать не отсортированные значения, а **исходные номера** элементов:

```python
a = [30, 10, 20]
order = sorted(range(len(a)), key=lambda i: a[i])
print(order)           # [1, 2, 0] — сначала a[1]=10, потом a[2]=20, потом a[0]=30
```

## 11. Типичные олимпиадные приёмы с сортировкой

### 11.1. Сжатие координат

Значения до `10⁹`, но их всего `n ≤ 10⁵`. Заменим каждое значение на его **ранг** (номер среди различных значений) — дальше можно использовать массивы размера `n`, сортировку подсчётом и т. п.

```python
a = [100, 5, 1000000000, 5, 42]
vals = sorted(set(a))                     # [5, 42, 100, 1000000000]
rank = {v: i for i, v in enumerate(vals)}
compressed = [rank[x] for x in a]
print(compressed)                         # [2, 0, 3, 0, 1]
```

### 11.2. Метод событий (сканирующая прямая)

Задача: даны отрезки `[l, r]` — сколько максимум отрезков покрывают одну точку?
Превращаем каждый отрезок в два события: «открылся» (+1) в точке `l` и «закрылся» (−1) в точке `r`. Сортируем события и идём слева направо.

```python
def max_overlap(segments):
    events = []
    for l, r in segments:
        events.append((l, +1))
        events.append((r, -1))
    # при равной координате сначала открытие (+1): отрезки с общим концом считаем пересекающимися
    events.sort(key=lambda e: (e[0], -e[1]))
    cur = best = 0
    for _, delta in events:
        cur += delta
        best = max(best, cur)
    return best


print(max_overlap([(1, 5), (2, 6), (4, 8), (7, 9)]))   # 3 — в точке 4 или 5
```

Порядок событий с одинаковой координатой — самое частое место ошибки: всегда проверяйте по условию, касаются ли отрезки концами.

### 11.3. Жадность после сортировки

**Максимум непересекающихся отрезков** (задача о заявках): сортируем по **правому концу** и берём отрезок, если он начинается после конца последнего взятого.

```python
def max_non_overlapping(segments):
    segments = sorted(segments, key=lambda s: s[1])
    count = 0
    last_end = float("-inf")
    for l, r in segments:
        if l > last_end:          # строго >, если касание концами запрещено
            count += 1
            last_end = r
    return count


print(max_non_overlapping([(1, 3), (2, 5), (4, 6), (6, 8), (7, 9)]))   # 3: (1,3), (4,6), (7,9)
```

### 11.4. Два указателя по отсортированному массиву

Есть ли пара с суммой `x`? После сортировки — O(n) двумя указателями с концов (подробнее — в конспекте по динамическому массиву, раздел 8.1).

```python
def has_pair_with_sum(a, x):
    a = sorted(a)
    i, j = 0, len(a) - 1
    while i < j:
        s = a[i] + a[j]
        if s == x:
            return True
        if s < x:
            i += 1
        else:
            j -= 1
    return False
```

## 12. Частые ошибки

1. **`a = a.sort()`** — `sort()` возвращает `None`. Либо `a.sort()`, либо `a = sorted(a)`.
2. **Сортировка строк вместо чисел.** После `input().split()` элементы — строки, и `sorted(["10", "9", "2"])` даст `['10', '2', '9']`. Не забывайте `map(int, ...)`.
3. **Быстрая сортировка с фиксированным pivot** (первый/последний элемент) падает до O(n²) на отсортированном массиве. Берите случайный pivot — или просто используйте встроенную `sorted`.
4. **Глубина рекурсии.** Рекурсивные сортировки на Python при плохом разбиении упираются в лимит рекурсии (~1000). Merge sort безопасен (глубина `log n`), quicksort — только со случайным pivot.
5. **Потеря устойчивости** в самописной сортировке: `<` вместо `<=` при слиянии или `>=` вместо `>` во вставках — равные элементы меняются местами.
6. **Сортировка подсчётом при огромном диапазоне** — `[0] * 10**9` не поместится в память. Сначала сожмите координаты.
7. **`key=lambda p: -p[0]` для строк** — строку нельзя сделать отрицательной. Используйте `reverse=True` или двойную устойчивую сортировку.
8. **Сортировка внутри цикла.** Если сортировать массив на каждой итерации, получится O(n² log n). Обычно достаточно отсортировать один раз, а для «добавить и держать отсортированным» нужна куча или `bisect.insort`.

## 13. Шпаргалка

```python
a.sort()                                  # на месте, O(n log n), устойчиво
b = sorted(a)                             # новый список
sorted(a, reverse=True)                   # по убыванию
sorted(a, key=lambda x: (x[1], -x[0]))    # несколько ключей
sorted(range(n), key=lambda i: a[i])      # индексы в порядке сортировки

from functools import cmp_to_key
sorted(a, key=cmp_to_key(cmp))            # свой компаратор: cmp(a, b) → -1 / 0 / 1

# своя сортировка нужна, когда:
# — надо что-то посчитать по ходу (инверсии → merge sort)
# — значения маленькие целые (→ counting sort, O(n + k))
# — просят реализовать конкретный алгоритм
```

| Нужно | Бери |
|---|---|
| просто отсортировать | `sorted` / `.sort()` |
| число инверсий | merge sort с подсчётом |
| значения в маленьком диапазоне | counting sort |
| k минимальных из огромного потока | куча (`heapq.nsmallest`) |
| держать отсортированным при вставках | `bisect.insort` (O(n)) или куча |

4. Отсортируйте список пар `(имя, балл)` по баллу по убыванию, а при равенстве — по имени по алфавиту одной строкой.
5. Сколько обменов сделает сортировка пузырьком на массиве `[4, 3, 2, 1]`?
6. Почему при слиянии в merge sort пишут `left[i] <= right[j]`, а не `<`?
7. Почему introsort при слишком глубокой рекурсии переключается именно на пирамидальную сортировку, а не на сортировку слиянием?
8. Почему `sorted()` на уже отсортированном списке работает за O(n)?

<details>
<summary>Ответы</summary>

1. **Вставками** (и пузырёк с флагом `swapped`): каждый элемент сравнивается один раз с соседом слева и остаётся на месте — O(n). Выбор всегда делает O(n²) сравнений, чтобы найти минимум.
2. Pivot всегда оказывается минимумом, разбиение даёт части размера `0` и `n − 1`. Получается `n` уровней рекурсии, на каждом O(n) работы → O(n²).
3. Сортировкой подсчётом: массив `cnt` из 101 элемента, O(n + 101) = O(n).
4. `sorted(pairs, key=lambda p: (-p[1], p[0]))`.
5. **6** — это число инверсий: каждая из `4·3/2 = 6` пар стоит в неправильном порядке.
6. Чтобы при равенстве брать элемент из **левой** половины — он стоял в исходном массиве раньше. Так сохраняется устойчивость.
7. Пирамидальная сортировка гарантирует O(n log n) и работает **на месте**, без доп. памяти — как и сам introsort. Сортировке слиянием нужна память O(n).
8. Timsort находит в нём **один** пробег длины n (n − 1 сравнение), и сливать ничего не нужно.
