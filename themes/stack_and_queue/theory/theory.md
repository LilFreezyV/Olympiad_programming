## 1. Что такое стек и очередь

Обе структуры хранят набор элементов, но разрешают только **две основные операции**: добавить элемент и достать элемент. Разница — **какой** элемент достаётся.

| | Стек (stack) | Очередь (queue) |
|---|---|---|
| Принцип | **LIFO** — Last In, First Out | **FIFO** — First In, First Out |
| Достаём | последний добавленный | первый добавленный |
| Аналогия | стопка тарелок | очередь в столовой |

```
Стек:  push 1, 2, 3            Очередь:  push 1, 2, 3

  │ 3 │ ← pop вернёт 3           вход → [3, 2, 1] → выход
  │ 2 │                                          ↑
  │ 1 │                                  pop вернёт 1
  └───┘
```

> **Аналогия.** Стек — стопка тарелок: новую кладут сверху, и берут тоже сверху. До нижней тарелки не добраться, пока не снимешь все верхние. Очередь — касса в магазине: кто первым встал, того первым и обслужат.

Обе структуры поддерживают все операции за **O(1)**. Именно поэтому их и используют: они не умеют ничего лишнего, но то, что умеют, делают мгновенно.

## 2. Операции и названия

| Действие | Стек | Очередь |
|---|---|---|
| добавить | `push(x)` | `push(x)` / `enqueue(x)` / `add(x)` |
| достать и удалить | `pop()` — верхний | `pop()` / `dequeue()` — первый |
| посмотреть без удаления | `peek()` / `top()` | `front()` |
| проверить пустоту | `is_empty()` | `is_empty()` |
| размер | `size()` / `len()` | `size()` / `len()` |

Все — O(1).

## 3. Стек

### 3.1. Стек на связном списке (пример с занятия)

Код из `code/stack.py`. Новый элемент кладём **в голову** списка — там же его и забираем.

```python
class Node:
    def __init__(self, x):
        self.x = x
        self.next = None


class Stack:
    def __init__(self):
        self.head = None

    def add(self, x):
        newNode = Node(x)
        if not self.head:
            self.head = newNode
        else:
            newNode.next = self.head
            self.head = newNode

    def pop(self):
        r = self.head.x
        self.head = self.head.next
        return r
```

Как меняются ссылки при `add(1)`, `add(2)`:

```
после add(1):   head ──▶ [1 | None]

после add(2):   newNode = [2 | •]
                newNode.next = head     [2 | •]──▶[1 | None]
                head = newNode          head ──▶ [2 | •]──▶[1 | None]
```

Ветка `if not self.head` на самом деле не нужна: если стек пуст, `newNode.next = self.head` просто запишет `None`. Можно короче:

```python
    def add(self, x):
        new_node = Node(x)
        new_node.next = self.head
        self.head = new_node
```

### 3.2. Стек на списке Python

У `list` операции `append` и `pop()` работают с **концом** массива за O(1) (амортизированно — см. конспект про динамический массив). Это и есть готовый стек:

```python
stack = []
stack.append(1)       # push
stack.append(2)
stack.append(3)
print(stack[-1])      # peek → 3
print(stack.pop())    # pop  → 3
print(stack.pop())    # pop  → 2
print(len(stack))     # 1
print(not stack)      # пуст? → False
```

На олимпиадах почти всегда используют именно это.

## 4. Очередь

### 4.1. Очередь на связном списке (пример с занятия)

Код из `code/queue.py`. Нужны **две** ссылки: `head` (откуда забираем) и `tail` (куда добавляем). Если хранить только `head`, чтобы добавить в конец, пришлось бы каждый раз идти по всей цепочке — O(n).

```
head                     tail
 ↓                        ↓
[1 | •]──▶[2 | •]──▶[3 | None]
 ↑                        ↑
 pop отсюда         add сюда
```

Аккуратная версия с проверками:

```python
class Queue:
    def __init__(self):
        self.head = None
        self.tail = None
        self.size = 0

    def add(self, x):
        new_node = Node(x)
        if self.tail is None:          # очередь пуста
            self.head = new_node
            self.tail = new_node
        else:
            self.tail.next = new_node
            self.tail = new_node
        self.size += 1

    def pop(self):
        if self.head is None:
            raise IndexError("queue is empty")
        r = self.head.x
        self.head = self.head.next
        if self.head is None:          # забрали последний элемент —
            self.tail = None           # хвост тоже должен стать None!
        self.size -= 1
        return r

    def front(self):
        return self.head.x

    def __len__(self):
        return self.size


q = Queue()
for i in range(1, 4):
    q.add(i)
print(q.pop(), q.pop())   # 1 2
q.add(4)
print(q.pop(), q.pop())   # 3 4
```

**Важная деталь в `pop`:** если после удаления очередь опустела, нужно обнулить и `tail`. Иначе `tail` продолжит указывать на уже удалённый узел, и следующий `add` прицепит новый элемент к нему, а `head` останется `None` — элемент «потеряется».

```
Очередь [5]. pop() без обнуления tail:
    head = None,  tail ──▶ [5 | None]     ← tail указывает на удалённый узел
add(6):
    tail не None → tail.next = [6]        ← прицепили к «мёртвому» узлу
    head всё ещё None → очередь выглядит пустой
```

### 4.2. Почему не `list.pop(0)`

```python
q = []
q.append(x)      # O(1)
q.pop(0)         # O(n)! — все оставшиеся элементы сдвигаются влево
```

На `10⁵` операциях это `10¹⁰` сдвигов — Time Limit. Для очереди в Python используют `collections.deque`:

```python
from collections import deque

q = deque()
q.append(1)          # в конец
q.append(2)
q.append(3)
print(q.popleft())   # из начала → 1, O(1)
print(q[0])          # посмотреть первый → 2
print(len(q))        # 2
```

### 4.3. Очередь на массиве с указателем начала

Если известно, сколько всего элементов пройдёт через очередь (например, в BFS — не больше числа вершин), можно вообще не удалять элементы, а просто двигать индекс начала:

```python
q = [start]
head = 0
while head < len(q):
    v = q[head]
    head += 1
    # ... q.append(сосед) ...
```

Быстро и просто, но «съеденные» элементы продолжают занимать память.

### 4.4. Очередь на двух стеках

Классическая задача: сделать очередь, имея только стеки. Держим два стека: `inbox` для добавления и `outbox` для извлечения. Когда `outbox` пуст — перекладываем в него всё из `inbox`, порядок при этом разворачивается.

```python
class QueueOnStacks:
    def __init__(self):
        self.inbox = []
        self.outbox = []

    def push(self, x):
        self.inbox.append(x)

    def pop(self):
        if not self.outbox:
            while self.inbox:
                self.outbox.append(self.inbox.pop())
        return self.outbox.pop()


q = QueueOnStacks()
q.push(1); q.push(2); q.push(3)
print(q.pop())   # 1
q.push(4)
print(q.pop(), q.pop(), q.pop())   # 2 3 4
```

Каждый элемент перекладывается **ровно один раз**, поэтому `pop` работает за O(1) амортизированно. Эта идея пригодится для «очереди с минимумом».

## 5. Типичные задачи на стек

### 5.1. Правильная скобочная последовательность

Строка из `()[]{}` — правильная ли? Открывающие скобки кладём в стек, на закрывающую — проверяем, что сверху лежит парная.

```python
def is_balanced(s):
    pairs = {")": "(", "]": "[", "}": "{"}
    stack = []
    for ch in s:
        if ch in "([{":
            stack.append(ch)
        else:
            if not stack or stack[-1] != pairs[ch]:
                return False
            stack.pop()
    return not stack               # в конце стек должен быть пуст


print(is_balanced("([]{})"))   # True
print(is_balanced("([)]"))     # False
print(is_balanced("(("))       # False
```

### 5.2. Вычисление выражения в обратной польской записи

В записи `3 4 + 2 *` операция идёт **после** операндов, скобки не нужны. Числа кладём в стек, на операцию — снимаем два числа и кладём результат.

```python
def eval_rpn(tokens):
    stack = []
    for t in tokens:
        if t in "+-*":
            b = stack.pop()        # сначала снимается ВТОРОЙ операнд
            a = stack.pop()
            if t == "+": stack.append(a + b)
            if t == "-": stack.append(a - b)
            if t == "*": stack.append(a * b)
        else:
            stack.append(int(t))
    return stack[-1]


print(eval_rpn("3 4 + 2 *".split()))   # (3 + 4) * 2 = 14
print(eval_rpn("5 1 2 + 4 * + 3 -".split()))   # 5 + (1 + 2) * 4 - 3 = 14
```

### 5.3. Ближайший больший элемент справа (монотонный стек)

Для каждого `a[i]` найти первый элемент правее, который больше него. Наивно — O(n²). Со стеком — O(n).

Идея: в стеке храним индексы элементов, для которых ответ ещё **не найден**. Их значения идут по убыванию. Когда приходит новый элемент, он становится ответом для всех меньших на вершине стека.

```python
def next_greater(a):
    n = len(a)
    ans = [-1] * n
    stack = []                        # индексы, значения по убыванию
    for i in range(n):
        while stack and a[stack[-1]] < a[i]:
            ans[stack.pop()] = a[i]
        stack.append(i)
    return ans


print(next_greater([2, 1, 5, 3, 4]))   # [5, 5, -1, 4, -1]
```

Каждый индекс кладётся и снимается со стека не больше одного раза → O(n). Этот приём лежит в основе многих задач: «максимальный прямоугольник в гистограмме», «сколько дней до потепления» и т. п.

### 5.4. Стек с минимумом за O(1)

Храним в стеке пары `(значение, минимум среди этого и всех ниже)`:

```python
class MinStack:
    def __init__(self):
        self.a = []

    def push(self, x):
        cur_min = min(x, self.a[-1][1]) if self.a else x
        self.a.append((x, cur_min))

    def pop(self):
        return self.a.pop()[0]

    def get_min(self):
        return self.a[-1][1]


s = MinStack()
for x in [5, 3, 7, 2]:
    s.push(x)
print(s.get_min())   # 2
s.pop()
print(s.get_min())   # 3
```

Если построить очередь на двух таких стеках (раздел 4.4), получится **очередь с минимумом** — тоже за O(1) амортизированно.

## 6. Типичные задачи на очередь

### 6.1. Обход в ширину (BFS)

Главное применение очереди — поиск кратчайшего пути в невзвешенном графе (или лабиринте). Вершины обрабатываются **в порядке удалённости** от старта именно потому, что очередь FIFO.

```python
from collections import deque

def bfs(graph, start):
    dist = {start: 0}
    q = deque([start])
    while q:
        v = q.popleft()
        for u in graph[v]:
            if u not in dist:
                dist[u] = dist[v] + 1
                q.append(u)
    return dist


graph = {1: [2, 3], 2: [4], 3: [4], 4: [5], 5: []}
print(bfs(graph, 1))   # {1: 0, 2: 1, 3: 1, 4: 2, 5: 3}
```

Если заменить очередь на стек, получится обход в глубину (DFS), и расстояния перестанут быть кратчайшими.

### 6.2. Моделирование процессов

«Очередь к кассе», «иосифова задача» (люди стоят по кругу, выбывает каждый k-й), «карточная игра в пьяницу» — всё это прямое моделирование очередью.

```python
from collections import deque

def josephus(n, k):
    """n человек по кругу, выбывает каждый k-й. Кто останется?"""
    q = deque(range(1, n + 1))
    while len(q) > 1:
        q.rotate(-(k - 1))     # k-1 человек переходят из начала в конец
        q.popleft()            # k-й выбывает
    return q[0]


print(josephus(7, 3))   # 4
```

## 7. Частые ошибки

1. **`pop` из пустой структуры.** `self.head.x` при `head = None` → `AttributeError`, `[].pop()` → `IndexError`. Проверяйте пустоту перед извлечением.
2. **`pop` очереди не обнуляет `tail`,** когда очередь опустела (раздел 4.1). Следующий `add` прицепит элемент к удалённому узлу.
3. **`pop` не возвращает значение.** Забыли `return r` — метод вернёт `None`.
4. **`list.pop(0)` в качестве очереди** — O(n) на операцию. Используйте `deque.popleft()`.
5. **Путаница порядка операндов** в обратной польской записи: со стека сначала снимается **второй** операнд (`b`), потом первый (`a`). Для `-` и `/` это важно.
6. **Удаление по индексу из середины очереди.** Если задача требует удалять или читать `i`-й элемент, это уже не очередь — нужна другая структура.

## 8. Шпаргалка

```python
# стек
stack = []
stack.append(x)          # push
stack.pop()              # pop
stack[-1]                # peek
not stack                # пуст?

# очередь
from collections import deque
q = deque()
q.append(x)              # push в конец
q.popleft()              # pop из начала
q[0]                     # первый элемент
not q                    # пуста?

# НЕ использовать для очереди: list.pop(0) — O(n)
```

| Задача | Структура |
|---|---|
| скобки, отмена действий (Ctrl+Z), рекурсия «вручную» | стек |
| ближайший больший/меньший, гистограмма | монотонный стек |
| кратчайший путь в невзвешенном графе | очередь (BFS) |
| моделирование «кто первый пришёл» | очередь |
| добавлять/удалять с обоих концов | дек (`themes/deque`) |
| доставать минимум/максимум | куча (`themes/heap`) |

## 9. Вопросы для самопроверки

1. В пустой стек положили `1, 2, 3`, сделали `pop`, положили `4`, сделали два `pop`. Что осталось в стеке?
2. Тот же вопрос для очереди.
3. Почему для очереди на связном списке нужна ссылка на `tail`, а для стека хватает `head`?
4. Почему `list.pop(0)` не подходит для очереди, а `list.pop()` для стека подходит?
5. Какая сложность у алгоритма «ближайший больший справа» на монотонном стеке, если внутри `for` есть `while`?

<details>
<summary>Ответы</summary>

1. **`[1]`.** После `pop` → `[1, 2]`, после `push 4` → `[1, 2, 4]`, два `pop` снимают 4 и 2.
2. **`[4]`.** После `pop` (ушла 1) → `[2, 3]`, после `push 4` → `[2, 3, 4]`, два `pop` забирают 2 и 3.
3. В стеке добавление и удаление происходят с **одного** конца — с головы. В очереди — с **разных**: добавляем в конец, забираем из начала. Без `tail` добавление стоило бы O(n).
4. `pop()` удаляет последний элемент — ничего сдвигать не нужно, O(1). `pop(0)` удаляет первый — все остальные сдвигаются влево, O(n).
5. **O(n).** Каждый индекс попадает в стек один раз и снимается не больше одного раза, поэтому суммарно `while` выполняется не больше `n` раз за всю работу.

</details>
